# 配色合同（结构化）· 跨主题版 v1

用途：在**没有画风参考图**的场景下，把「指定一套颜色 + 指定落点区域」写成可校验、可冻结的合同，
由实验层组装进生图请求。只做配色与落点，不做画质或美感要求。

正式字段在 `prompts/color-knowledge/cross-theme-palette-v1.json` 的 `contract` 段；本文件说明每个字段的含义与约束。

## 字段

| 字段 | 含义 | 约束 |
|---|---|---|
| `contract_id` / `version` | 合同标识与版本 | 合同内容变化必须换新版本号并换新输出目录 |
| `contract_hash` | 正式合同的 hash | 由实验层对合同正文重算并核对；不一致即拒绝运行 |
| `colors.main` | **主色**：环境主导色的色名与近似色值 | 必须有 `name` / `hex` / `regions` |
| `colors.accent` | **点缀色**：小面积高彩度色的色名与近似色值 | 必须有 `name` / `hex` / `regions`，并声明「不得替换成近似色」 |
| `allowed_neutrals` | **允许中性色**：主色系之外可用的低彩度色（明度层次用） | 只允许低彩度中性色，不允许引入第二种有彩色主色 |
| `protected` | **保护色**：不属于配色授权范围的主体固有颜色 | 必须逐条给出 `region`，且与 `regions.authorized` 不重叠 |
| `regions.mapping` | **区域落点映射**：合同区域 → 每个主题里**已经存在**的区域 | 每个主题都必须把全部合同区域映射到已有区域；不得新增物件 |
| `regions.authorized` | **授权改色区域**：允许按合同改色的区域 | 只允许既有的点缀承载区；不得包含保护色区域 |
| `regions.forbidden_additions` | 禁止新增的物件/元素 | 用于挡住「为了满足点缀色而加一条新丝带/新道具」 |
| `negative` | 其它硬性禁止（加人、改时间天气等） | 与保护块一致 |

## 冲突检查（离线，运行前必须通过）

1. `authorized` 与 `protected` 的**区域名不得重叠**；重叠即视为「保护色与授权改色冲突」，**停下说明**，
   不通过关闭身份或质量门禁绕过（本项目不对任何门禁做开关）。
2. 每个主题的 `mapping` 必须覆盖全部合同区域，并且映射目标都在该主题的 `existing_regions` 里。
3. 点缀区域数量必须与「落点」声明一致（本版为 3 处：腰带式束带 + 左右两只鞋的既有蝴蝶结）。
4. 若某个主题缺少某个既有区域，必须显式声明 `unmappable`，运行时**跳过该区域并记录**，不得悄悄新增物件补足。

## 首版范围

- 只用于 **Gemini 无参考图直出**（`image_paths` 为空）。
- **有有效画风参考图时禁止选择或注入配色**：`retention`/`assemble_*` 侧校验参考图存在即拒绝注入
  （本轮只做校验函数与回归，不接生产 GUI）。
- 未启用配色时**原请求逐字不变**，也不额外调用任何模型。
