## 生效范围与流程

`prompts/gpt-image-optimize/config.json` 和缺省值新增 `refine_enabled=true`。GPT Tab 的生图/编辑开启自动重绘，以及图片分析的 GPT 自动链开启保真重绘时，使用以下流程：

1. 分析首图实际材质、身份颜色、绘画介质、人体连接和需要清理的区域。不确定或已有明显人体错误，保留首图，不继续收费图片步骤。
2. 仅用首图修人物衣装：保留主要裂口、受损状态、裸露范围、材质和金边路线，整理诊断中明确的微碎结构。
3. 比较原图、工序输入和候选，逐项检查人体、身份、瞳色色相/明度/饱和度、衣装大结构、主要破损、材质、画法、构图及物件。全部明确通过才采用人物候选。
4. 仅用通过检查的人物图修诊断中的背景表面。保留场景原材质、物件、透视及光影，不把石板规则套在草地等其他场景上。
5. 再检查背景候选，同时与原图和已接受人物图比较。失败、异常、比例错误或超时，返回最近通过的输入；人物步骤失败不会进入背景步骤。

每张最多 **2 次图片请求（各360秒）+3 次文本请求（各180秒）**，不自动重试，不接旧局部新增清除分支。未诊断到适用区域时可跳过相应图片步骤。审计不确定一律拒绝候选。所有候选和完整请求、分析原文、结论、源图 hash 保留在输出目录的 `refine-*-refine.json` 中。Windows 临时文件锁只重试本地原子改名，不重发 API。

画风参考仍参与 GPT 首图；refine 图片阶段只传当前源图，继承其画法与内容。模型仍从当前重绘配置读取（用户此前已选择 `gemini-3.1-flash-image`），每张图片分别按源图方向匹配模型支持的比例。

自动 refine 已包含衣装修复，跳过重复的衣装重绘；保存的衣装开关仍保留，关闭自动重绘时可独立使用。原有本地结构线/色调/加墨及分析链质量、身份、人体检查保留。费用显示按最多2图3文本计算，等待预算增加到1260秒的 refine 预留；原有外围工序预算仍保守保留。

## 兼容与使用

- 必须重启应用加载新代码；本次没有代为重启。新任务在开启自动重绘时生效。
- 旧成功断点照常复用，不偷偷重新收费。要对旧图应用新流程，需显式建立新的自动任务并从 GPT 首图执行。
- 独立手动重绘仍按编辑框指令执行，不强制进入 refine。
- 设置 `refine_enabled=false` 恢复旧自动单步保真流程；实验调用 `content_guard=false` 的默认路径保持原行为。
- 公共 API 配置和艺术家画风参数未因本里程碑修改。style 子模块提交的是与该流程配套的画风保留合同记录；同步工具确认0处字段更新。两个 JSON 非逐字段完全相同：子模块为 tid、komori-hikki-style 保留了本地缺失的 `gemini_content_field` 默认值，同步工具按原规则不删除这些字段。
