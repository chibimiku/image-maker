# Refine审计接口异常自动重试

用户要求断点审计失败时自动重试3次。生产refine各阶段的文本审计（包括历史分步和UI只补审计）首次请求之后最多追加3次，共4次；只重复相同system/user/images的文本调用，不重复图片生成，不跳过审计。源图diagnosis仍单次。

重试范围：超时、连接/TLS错误、HTTP429与5xx。HTTP400/401等请求或鉴权错误、JSON解析错误、预算拒绝不重试。正常返回的fail/不确定报告不重试，继续沿用原门禁和回退；取消在每次派发前及1/2/3秒短暂退避中检查。四次接口异常仍保留输入、候选和断点，用户可显式继续。

记录每次attempt的序号、请求/返回/失败状态、开始/结束时间和错误；正在重试写retrying，UI显示重试序号/请求次数，成功后清理当前错误但保留失败attempt历史。独立实验预算每次仍通过guarded_text_call预留/结算，硬上限或阶段上限不足时提前停止，不擅自扩大预算。成功/失败请求的实际收费由服务方决定，不假定断连无收费。

默认hybrid逻辑最多5个文本阶段（诊断+4审计）；包含异常重试的最坏尝试数为17，总网络预留4*360+17*180=4500秒。费用上限按17文本保守估算；无异常仍是原次数。源诊断不重试；图片请求仍无自动重试。

四套211项离线回归通过，覆盖一次异常恢复、三次异常后恢复、四次耗尽、恢复后返回fail不重试、非网络错误不重试、HTTP分类、取消时不派发下一次，以及UI/CLI/分析链最长等待预算。未发付费测试请求、未自动续跑用户刚失败的任务、未重启App。重启加载后新任务及显式断点续审采用新重试逻辑，历史失败记录不改写。
