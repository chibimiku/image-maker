# 单图分析任务意图与剪贴板目录排查（2026-10-05）

## 已确认的代码问题

- `on_process_finished` 原先读取回调发生时的保存与自动生图勾选框。分析进行中切换选项，会改变之前提交的任务；生图通道也随当前界面改变。
- 生图未启动时原先使用 `require_products=False` 按只分析成功收尾；分析线程退出的兜底也无条件标绿。无最终产物的管线可能一直等待。
- 剪贴板快照重跑传入磁盘路径，原先被记成文件来源，允许把分析 JSON/TXT 写进快照目录并跳过生成。

## 修复

提交时把保存方式、生成目标、通道存进 `meta_analysis_options` 与历史记录 `analysis_options`，完成回调沿快照执行。显式生成目标优先于仅保存选项；显式空目标用于只分析。自动生成按提交时的通道执行。

PIL 图片与 `CLIPBOARD_SNAPSHOT_DIR` 内的文件均认作剪贴板来源，不适用原图目录保存。快照仍可用于重跑，不改动已有图片或历史分析结果。

生图启动失败（含抛异常）、部分目标启动失败、无最终产物、分析线程没有正常完成收尾，都记录错误并标红；保留已经保存的分析结果。正在运行的生图/后处理仍保持进行中，避免抢跑。

## 磁盘核对

排查时 `cache/temp/single-analyzer-clipboard/` 递归共有 389 个文件，全部为 `.png`；其中 20 个修改时间属于 2026-10-04。未发现 JSON/TXT 被误存到该目录，无需搬迁。

2026-10-04 日期目录顶层有 28 份分析 JSON（27 份源路径为空、1 份有文件路径），2026-10-05 当时有 12 份（5 份源路径为空、7 份有文件路径）；没有引用剪贴板快照路径的分析 JSON。空源路径符合直接剪贴板分析的旧行为，不能仅凭此判定单个任务实际生成是否成功。保存请求的日志没有保留所排查的界面勾选与跳过信息，因此本次确认的是代码可复现路径，不能把用户遇到的具体一次无图任务归因到其中某一分支。
