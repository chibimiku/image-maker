# DeepSeek 执行任务：画风相似度严格受控实验

协议版本：1.0，2026-10-06。这是待执行协议，不是已取得的结果。先读全文，冻结实验包后再计算。允许技术失败重试；禁止按分数挑图、挑模型或挑成功尝试。

## 1. 任务与结论边界

验证 `utils/style_similarity.compare_images()` 的八组全图指标，以及 `utils/style_face_metrics.py` 的十三组面部/发丝指标，能否支持画风检索、候选排序和局部差异判断。

分别回答四个问题，不合并成一句“可靠”：

1. **实现正确性**：同图、对称性、缓存、入口一致性是否正确？
2. **画风效度**：是否识别同画风不同内容，而不是只匹配配色和构图？
3. **局部效度**：正确定位后，指标是否响应指定局部变化？自动定位又损失多少可靠性？
4. **候选排序效度**：结果是否与独立人类盲评一致？现有视觉模型复核是否与盲评一致？

历史两张 Gemini 测试只作问题线索，不作验收集：见 `GEMINI-SIMILARITY-TEST-20261006.md`。当时全图计算成功，但自动定位精度未通过、未运行正式视觉复核；Sakurapion 产物更接近 Puracotte 参考，尚不能区分生成失败与指标混杂。

执行本协议时不要宣称当前方法是 LoRA loss，不输出未经校准的综合相似百分比，不把模型自评当成人类评价。

## 4. E0：实现一致性与错误传播

零收费调用，至少使用4张原作品和历史两张 Gemini 图，检查：

1. 同图：Gram/AdaIN/LPIPS 对照共享 runner 的自检容差；CSD≈1；本地四组≈1。十三项只对定位充分且可比的项检查，缺失不可补成1。
2. A↔B：同设备下结果对称，绝对误差≤`1e-6 + 1e-5×max(abs(a),abs(b))`；超过时保留原始值查明原因。
3. 重复、成功缓存、进程重启复算数值一致；图片或区域 hash 改变后旧结果不能被误复用。
4. 双图 UI、提取页与 CLI 输入相同 manifest/区域/设备，所得值和状态一致。UI 可用独立 offscreen 实例，不加载/重启用户现有 app。
5. 不可读图片、错误区域 hash、闭眼、遮挡、视角不同、配对缺失必须给具体状态；不得标成完整成功。

产出 `E0-checks.json`，逐项 pass/fail/error。关键正确性失败时暂停主验收，修复后作为新代码版本重跑受影响计算；无须重复成功生图。

## 5. E1：原作品画风辨别（主要效度实验）

### 5.1 数据

目标4种画风，优先 Puracotte、Sakurapion、Kishida Mel、TID，但以来源可验证的实际原作品为准。标签有争议则预先替换并记录，不能根据指标表现换画风。

先做试验集：每画风12个独立作品，共48张；6张参考、6张 query，共24次四分类检索。每个 query 与4个参考集分别比较，共96个聚合单元、576个逐图配对。
同作品的裁剪、放大、改色、转载、同图多个角色均属于同一 work_id，不能跨 split。近重复图也不得跨 split；检测并人工核查后冻结。
各画风尽量平衡头像/半身/全身、亮暗、背景密度；仍有不平衡必须列出，不能称已完全消除混杂。

### 5.2 分析

每个全图指标独立计算每参考集均值：Gram/AdaIN/LPIPS 取最低，CSD/四组本地统计取最高。并列 tolerance 沿 E0 数值容差，保留并列，主准确率中并列不算正确；另报分摊并列准确率。
不临时加权、不按本批结果挑一项当“总分”。预注册 **CSD 为主画风检索指标**，其余全部作为次要/诊断指标。

输出每指标 Top-1、macro accuracy、各画风命中率、4×4混淆矩阵、同风格/异风格分布、错误 ID。区间按 query/work 取样，不能把576个相关配对当作576个独立样本；试验集同时报告精确计数及 Wilson 95%区间。
原作品检索失败直接说明指标存在效度问题，不能归咎于生图模型。

## 6. E2：内容与配色干扰对照

在查看指标前从 E1 每风格3张 query 冻结12张 anchor，每张选：

- P：同画风但人物/配色/构图明显不同的真实作品。
- N：不同画风但人物类型、亮暗、主配色、景别尽量相近的真实作品。

选择依据由不知道指标值的标注者填写；难以匹配则标为未满足，不强行充数。比较 `anchor→P` 与 `anchor→N`，每指标报告正确偏好率/并列/错误。拆开“配色匹配”“构图匹配”，不只报告总计。

另对这12张 anchor 做确定性干扰，不称为不改变画风的绝对真值：

| 变体 | 操作 | 用途 |
|---|---|---|
| N0 | 同尺寸无损 PNG 转存 | 编码基线 |
| N1 | HSV 色相轮转+30°，亮度通道不主动修改 | 配色敏感性 |
| N2 | 灰度强度×0.9（记录截断像素比例） | 明度敏感性 |
| N3 | 背景区域轻度高斯模糊，人物不变 | 背景细节干扰 |
| N4 | 相似尺寸内容整体平移画幅宽度5%，留白补边 | 构图/裁剪敏感性 |

必须冻结背景 mask、算法/参数和变体 hash；人工确认变体没有意外改人物结构。N1/N2 是敏感性诊断，不要求明度/配色指标“不变”。主要观察是否仅改颜色或背景就改变 CSD 画风预测，以及 LPIPS/Gram 等混杂程度。
N3/N4 涉及边界与插值，报告影响，不预设其画风必然完全相同。不得将所有分数尺度直接相减后比较大小。

## 7. E3：局部测量的受控响应

建立6个独立可读面部案例（两主画风各3），左右眼均可见、脸宽≥128px、眼宽≥32px。同一案例所有变体保持相同尺寸、主体、背景和其他部位。先取得正确的区域，而不是使用已知错误自动提案。

每案例针对以下8种干预建立原图、弱、中、强4级。修改区域以外的像素必须逐字节相同；局部变体的标注按已知几何变换更新，不能偷用原曲线导致采样错位。

| 干预 | 弱/中/强参数 | 预期主要响应 |
|---|---|---|
| 发丝粗细 | 选定细发丝宽度×1.15/1.30/1.50 | hair_fineness |
| 仅发丝断口 | 选定路径可见长度缺失5%/10%/20% | hair_continuity |
| 虹膜亮度 | 虹膜内部灰度×0.95/0.90/0.80 | eye_brightness |
| 上下眼睑间距 | 绕眼中心局部高度×1.05/1.10/1.20 | eye_height |
| 单眼宽度 | 两眼各绕自身中心宽度×1.05/1.10/1.20 | eye_width |
| 双眼间距 | 两眼向外各移脸宽0.005/0.01/0.02 | eye_gap |
| 睫毛笔画 | 固定2根可见睫毛宽度×1.15/1.30/1.50 | eyelashes |
| 上眼睑弧度 | 两眼端点固定，中段弓高×1.10/1.20/1.40 | eye_curvature |

每个干预必须有人核查 mask 和修改后的像素/曲线，记录实际达到的量；不能无痕完成的案例预先排除，不能拿明显修补痕迹冒充纯画法变化。不使用生成模型做这些主控干预，避免同时改变多个因素。真实图难控制时使用可控绘制图样作为机制测试，并明确其不代表真实图效度。

加两种负对照：头发区域外画黑线；眼区外加亮点。应不影响仅发丝/眼亮度的原始测量，误差沿 E0 容差。
报告目标指标原始分量、贴近度的剂量响应、单调方向命中率及非目标响应矩阵。部分维度存在必然耦合：变眼宽可同时改归一化眼高与弧度；加粗发丝也可改可见连续支持。冻结这些预期耦合，不要求所有其他项恒定。不得只给综合组分数而隐藏不响应的分量。
十三项中其余5项暂作诊断，未经对应受控干预不能宣称已验证。

## 8. E4：自动定位与人工标注误差

取E3的6个案例＋历史4张图，共10张；历史失败图必须保留。先为每图独立保存自动候选 A；再由两名实际人类标注者不看分数独立标注 H1/H2，其中一人隔至少24小时再标 H1-repeat。不能由 DeepSeek、另一模型或 agent 代填“人工确认”。

标注不必给不可见部分补线；没有3根可读细发丝就是 unavailable，不能描发束轮廓替代细发丝。眼睑、虹膜、睫毛、脸轮廓、头发 mask/path 都需叠图核查。

报告：

- 自动定位返回率、可用率、人工确认后完整配对覆盖率及逐项覆盖率，分母都包含失败图。
- 眼睑曲线到人工曲线的平均/95分位距离，除以人工眼宽；头发 mask IoU、发丝采样带完全位于有效头发内的比例、明显跑到皮肤/衣服的路径数。
- A↔H1、H1↔H2、H1↔H1-repeat 的原始分量差异、最终分数差异及排名翻转率；闭眼、遮挡、不同视角单列。
- 自动 proposal 始终保持 confirmed=false；复制到人工条件并经用户实际确认后才可设 true，原候选与历史版本保留。

人工尚未提供时完成自动部分与盲评包，报告 `awaiting_human`，其余不依赖人工的实验继续。不得用未经确认的暂定数值填正式均值。

## 9. E5：真实 Gemini 候选排序与独立复核

先复用历史成功两张图，补齐此前缺失的正式视觉复核。分别用各自风格的参考集和相同主体要求；不得把两种目标画风的候选混成同一目标的“最佳版本”。

新增生成的设计上限为2种画风×3个主体×3次独立重复＝18个计划槽位，仅 Gemini 带参考图，禁止 GPT 首图、后续重绘、挑选成功图；从当前配置冻结模型、模式、参考附件顺序、尺寸和分辨率。主体至少覆盖正面头像、正面半身与可读三分之四面部，两个画风对应主体正文完全一致。
**本文件创建不等于已发送这些新请求或已获追加18张费用额度。执行者先登记实际可用授权额度；不足时先复用已有图完成可执行部分，新增生成项标待额度。** 所有其他阶段不依赖这18张新图就继续。

运行真实 `app.py` 页面组装→线程→Gemini后端，或调用经入口一致性验证的共享组装函数；记录实际 entry。单独调用后端拼一套新提示词不能声称与 UI 一致。
成功图按槽位全部保留；风格差、主体错、结构差仍属于有效实验结果，不能作为技术失败重生成替换。API 拒绝、无图、无法解码按尝试账本记录，不能计画风成功。

冻结匿名包后，两名人类各自做至少24个A/B比较：在相同主体、相同目标画风下判断哪张更近参考，允许平局/无法判断，并记录线条、眼睛、头发、明暗、配色与背景依据。隐藏配置名、槽位/版本、指标和模型分数；A/B位置由冻结随机种子打乱，重复6个题检验个人一致性，重复题不重复计入主统计。
少于24个有效独立题时作为探索性结果；不得用跨主体排序凑题数。18槽位最多有18个组内组合，可增加已有同主体候选，不能擅自新增生图补数。

独立视觉模型复核也必须运行：沿现有12维评分、主体门禁和证据 schema；每批≤4候选、每批同一目标全部参考，缓存成功批次。模型看不到数值指标或人类答案。正序/倒序各运行一次并记录顺序敏感性，不能择优保留。
生成模型/定位模型/视觉复核若共享家族或端点，在报告中标记非独立；模型评分仅为另一个待验证测量。

按每指标与人类非平局共识比较方向一致率，按主体组分块统计 Kendall tau-b（足够组内样本时）；报告两人分歧率、重复题一致性、视觉模型与人的一致率、主体门禁结果。复制参考角色的图即使距离低，也不得当作成功候选。
把 `automatic_comparison` 和完整/部分状态写入对应实验状态，再调用共享报告器；未完成时显示真实覆盖数，不能只让“0/2 未运行”留在报告却宣称完成全链比较。

## 10. 重试、恢复与失败样本处理（必须执行）

每个技术 job 默认最多3次尝试＝首次＋2次重试。客户端、SDK、后端内置重试也计入实际 HTTP 尝试账本；先核对其策略，避免3×3叠乘。无法观测内置发送次数则标 `http_attempts_unknown`，不得宣称严格符合费用上限。

| 情况 | 允许措施 | 不能做的事 |
|---|---|---|
| 429/临时5xx/明确未发送的连接失败 | 同请求重试，建议30秒、90秒；Retry-After优先，冷却等待不占新请求 | 改正文、换图、换模型后仍算同一次 |
| 网络超时、响应丢失、提交状态未知 | 先查任务ID/输出/请求回放；服务支持时复用幂等键，同request hash；确认无结果后再补发 | 立刻重发可能已收费的生成；把unknown计失败未收费 |
| HTTP成功但JSON缺字段/格式错 | 保存原响应；本地解析修复先行；必要时同请求最多2次补充尝试，每次记录 | 丢弃原回答、偷偷填缺项、清空partial重跑全部 |
| 自动定位无效/不合理 | 先本地schema检查；最多2次同模型同prompt重试，全部保留并核查 | 挑数值最好的定位、改confirmed冒充人工校正 |
| 权重/本地推理/OOM/GUI预览失败 | 排查后复算受影响步骤，成功图片/定位照常复用 | 因预览报错重复收费生图 |
| 内容拒绝/持续4xx认证或配置错 | 查原因，保留refused/blocked；修正配置属于新记录，再运行受影响槽位 | 原请求无限重试、自动转其他生图通道 |
| 分数低、画风错、主体错、局部不清晰 | 保留为实际结果或预注册不可用状态 | 当技术错误重试直到满意 |

默认主结果用**首次技术完整的输出**；定位主结果亦用首次schema完整候选，即使几何错误。后续候选只作定位重试敏感性分析，不能替换主集。人工校正另列条件。
部分视觉结果按ID补缺，已成功批次复用；schema完整但评分低不能重评替换。达到上限后记 exhausted，继续其他独立job。
费用未知的生成请求在查明/额度足以覆盖最坏重复费用前不盲目补发；已计划3次独立生成重复与失败重试是不同槽位，分别统计。完成断点恢复时不得换run_id重置额度或重试计数。

## 11. 预注册验收规则与统计约束

以下为本项目拟定的工程门槛，不是行业公认标准。试验集用于诊断，**无论分数多高都不能单凭试验集宣称通用可靠**。

| 用途 | 最低条件 |
|---|---|
| 实现可用 | E0关键项全部通过；不存在错误hash复用或partial冒充完整 |
| 画风检索可作辅助 | E1试验集CSD Top-1≥80%、各风格≥2/3；E2困难对照正确偏好≥75%，并列主统计计不正确 |
| 局部辅助测量 | E3目标响应方向命中≥90%；局部负对照均通过；报告未验证维度与耦合 |
| 自动定位可默认参与可靠测量 | E4可用图覆盖≥90%，每个声称支持的维度有效覆盖≥80%；眼睑平均偏差≤眼宽2%、95分位≤5%；头发采样带有效率≥95%；还须人工间重复性通过。失败则保留人工模式 |
| 候选排序可作辅助 | 两人重复题一致率各≥80%、至少24个有效独立题；预注册主指标与人类共识方向一致≥80%，并且严重主体错误不被选为合格最佳 |

阈值精确计数向上取整。人工间重复性：连续分量ICC报告模型/95%区间，预注册使用双向随机、绝对一致性、单次测量 ICC(A,1)；点估计≥0.75且下界≥0.5方称初步可重复。不适合ICC的小样本/常数分量须报告原始差值，不强造ICC。

如果试验集通过，追加确认集：固定同4种画风、每种20个**新独立作品作为query**，参考集、代码、公式、主指标、阈值冻结，共80 query；不得用确认集训练权重或换算法。主指标Top-1仍≥80%、各风格≥70%，整体Wilson95%下界≥70%。确认集结果仍仅支持这些风格与覆盖场景，未测风格不得泛化。
局部/排序确认集同样必须是未参与调试的新案例；无法获取时结论降为初步。

按work/query或主体组做固定seed的2000次cluster bootstrap，报告95%区间及实际独立簇数；两图、几个配对不能提供稳定可靠性区间。次要指标明确探索性，多指标显著性检验如使用则预注册 Holm 校正；不靠“八项里有一项赢了”验收。
不可用/拒绝/门禁不合格均进覆盖率分母，效度指标只在预注册有效样本计算，并同步报告全样本保守结果；数据不足给inconclusive，不是pass。

## 12. DeepSeek 必须交付的结果

写 `docs/style-extraction/DEEPSEEK-SIMILARITY-CONTROLLED-RESULTS-<实际日期>.md`，附机器可读 `results.json`。即使部分受阻也交付，不用“后续再看”代替真实状态。

报告至少包含以下表格/证据：

1. 阶段状态：planned/running/complete/partial/awaiting_human/awaiting_budget/blocked；计划数、实际数、独立作品/主体数、缺项ID和原因。
2. 数据来源、split、近重复核查、混杂分布、冻结包/hash、代码/模型/设备；所有协议偏离单列。
3. E0逐项结果；E1八指标混淆矩阵与计数/区间；E2困难对照及各干扰翻转率；E3原始分量与剂量曲线；E4叠图、偏差/覆盖/重复性；E5盲评与视觉复核覆盖、分歧和排序一致性。
4. 完整尝试账本摘要：实际请求/重试/成功/partial/refused/exhausted/unknown/复用数量、计费已知与未知；链接每次失败原响应，不包含凭据。
5. 原作品参考、生成图、自动/人工区域、失败案例的可查看证据。只放精选成功拼图不合格。
6. 用途结论逐项填：实现通过否、全图辅助可靠否、自动局部可靠否、人工局部可靠否、自动选最佳可用否；依据到具体实验/ID，未做的写未验证。
7. 建议下一步：定位、公式、权重或参考集哪个环节需要修改，依据是什么；改算法须另开版本＋留出集验证，不回改本次失败结果。

最终消息必须给结果Markdown、JSON、HTML、账本和盲评包的实际路径，并用真实覆盖率说明已完成范围。不能把生成成功、全图status=ok、或单元测试通过写成整套画风方案已可靠。
