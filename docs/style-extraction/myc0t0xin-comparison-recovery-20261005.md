# myc0t0xin 比较失败与恢复

## 原问题

运行目录：`data/20261004/style-extraction/myc0t0xin/run-20261004-225929-156628/`。

5 轮及终审共 18 个候选，参考集 12 张。视觉比较在前三批完成后失败，缓存有 12 项，没有 `automatic_comparison`，也没有 `myc0t0xin` 画风配置。错误来自评分覆盖率校验；旧实现不保存失败批次响应，所以不能追溯究竟漏了或改写了哪些 ID。训练终审提示词的显示不等于选型结果。

NPU FP16 深度指标独立完成了 216 对比较，报告原先确实有 12 张源图及逐张数值，但没有视觉评分和主体门禁，使「指标完成」容易被误认为整个复核完成。

查看各轮图确认六张重绘都复制了参考 0 的角色、书本、椅子、酒红服装及月夜花框。旧流程强制完整画风图参与重绘；文字身份锁未阻止实际复制。已缓存的视觉评分识别了这些复制，问题不在于完全没有门禁，而在于后续复核中止、报告和 UI 未清楚展示部分结果。

2026-10-05 用户明确授权后，通过当前 `https://new.aigc2d.com/v1` / `gpt-5.6-luna` 补齐剩余 6 项，复用前 12 项，不重新生图。两次请求均通过校验；原始响应保存于 `comparison-audit/`。全量 18 项已写入结果 JSON 和 `automatic-comparison.json`，两份 HTML 报告已更新。

- 六张重绘及第 3 轮 GPT 首图被复制门禁排除；高画风分不能抵消门禁。

- 未写入画风配置，也没有重算深度指标。

## 程序修正

1. 比较显示批次、覆盖数量；显式传入本批精确 ID。格式校验失败重试一次，再失败保存原响应、缺失/未知/重复 ID 和部分已复核数据。
2. UI 将视觉复核失败与深度成功分别表达；失败时清空选型表、禁用导入，重新打开结果可恢复失败状态。
3. 深度报告加入原来的十二项评分及主体复核门禁，未完成项标「待复核」。原始参考图增加索引/路径；两份报告以 720px 嵌入预览展示，原始文件与计算输入不变。视觉报告约 4.60 MiB，深度报告约 4.05 MiB。
4. 新任务重绘默认 `reference_mode=none`，`clauses_without_image=true`：只发送 GPT 首图，同时传入本轮画风条款。UI 可显式选择完整画风图模式；打开历史默认恢复旧模式，逐轮记录模式。此改动尚未在线生图验证，不能宣称彻底解决复制；GPT 首图仍附带画风图，也可能泄露参考内容，仍需门禁。

需重启 app，再打开这次结果即可读取已补齐的评分，不需要重新训练。系统 Python 画风提示词包、布局、比较与深度比较回归 **34 项通过**；app 模块导入和修改文件编译通过。
