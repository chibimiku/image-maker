### 对 DeepSeek 报告的修正

1. 其 §4.5 写 A/B 两组 GPT 图都有白蝴蝶结，§5 B 又写没有，内部矛盾。实际 A 原包有明显白蝴蝶结，A opt1 是编起的侧发束，未见同样白蝴蝶结；B 未见明显发饰。不能把这项算成双方共有失败，也不能把 opt1 已改善之处抹掉。
2. A 主体只指定粉发、棕眼、湖边、春天。樱花、花朵和未指定服装不能一概视为内容违约；它们与参考图泄露不是同一个问题。B/C 的明确禁项应单独核对。
3. 坐姿全身被裁掉和年龄明显改变可以判主体偏离；联系表上看不清全部手指，不足以直接断言手部结构畸形。应区分不可读、遮挡与明确错误。
4. 全图平均亮度、暗部比例、碎线比例都受夜景、构图和内容影响。不能把源图子集均值当强制目标，也不能由碎线增多证明块面画法更好。C opt1 的问题应落到具体画法和局部可读性上，不能只归因于“太暗”。
5. 一包每场景每通道只有一个样本，原包重绘的清洁动漫退化也可能含随机波动。当前支持“部分方向有价值”，不足以支持“opt1 普遍更好”。

## 代码修复

修改范围：`tests/test_style_merge_validation.py`、`tools/style_merge_validate.py`、`modules/image_analysis/style_merge_validation.py`。未改通用生图固件、画风配置、候选原文、源数据或现有 GUI 模块；这些修复由验证 CLI 新进程直接加载。

- **真实打桩泄漏**：`_PatchGroup` 把 `patch.__enter__()` 返回的 Mock 保存下来，然后调用 Mock 的 `__exit__`，没有退出真正 patch。换成 `ExitStack`，正常结束、生成异常和部分进入失败都正确恢复。临时目录被删除不是这段代码的根因；防御性 mkdir 不能修复泄漏。它是验证测试辅助类缺陷，不能据此修改正常生产生图行为。
- **候选状态与报告链路**：统一复核状态文件路径；compare/deep/report 只给输出目录和场景即可从状态与 precheck 恢复候选模式，不再错误找 myc0t0xin 文件。移除重复定义的 `_load_entries`；保留自定义包名大小写；报告适配根级 prompt 包的字段来源与真实源图数量，删除候选复核报告里不相干的 myc0t0xin 第 5 轮短版说明。建议草稿按场景保存，避免不同场景互相覆盖。
- **整包选型正确性**：推荐保留完整候选名和任意 attempt 序号，不再截成首字母；明确指定不存在轮次时停止，不偷偷回退最终包；未给主体时读取实际候选记录，主体不一致时要求显式指定；候选缺少数据集时使用声明的兜底。
- **重绘失败继续拦截**：缺 manifest 时 partial 仍禁止通过；manifest 明确失败时即使返回了非 partial 文件也不通过；本地断点与跨包复用均排除 partial。DeepSeek 已恢复的 save_dir 赋值保留，并验证绝对路径与相对子目录解析。
- **预检与实跑参数一致**：GPT 首图实际调用透传组装出的 quality/size，避免报告参数与实发参数分叉。
