## 使用

- 图片分析页：旧「分析服装覆盖」仍只作用于分析搭配检查；同一行新增独立「衣装」。选 `Lolita 衣装`，通常用 `改款`。不要求打开「服装搭配检查」。
- gpt-image 专用页：在画风同一行选衣装；生图与编辑支持，单独重绘模式置灰。绘画风格和衣装选择互相独立。
- `只补全`：用户未指定衣服时补全目标衣装，已有衣服则保留。
- `改款`：未写衣服时补全，已有普通衣服时允许改成目标衣装；保留明确指定的颜色与标志性元素。
- `替换`：替换原衣物类别与裁剪。三个策略都尊重明确保留原服装/特定衣物的要求。
- `沿用原衣装`：不追加衣装提示词；默认关闭，原流程不变。

CLI：

```powershell
python tools/analysis_gpt_run.py --json <分析JSON> --style <画风名> --wardrobe lolita --wardrobe-policy reinterpret
```

`--wardrobe off` 关闭；未传 `--wardrobe` 时沿用分析 JSON 的任务快照。`--first-pass-only` 仍遵守原语义：只出首图，不做终审。此例未执行在线调用。

## 实现边界

预设在 `prompts/wardrobe/presets.json`，结构与搭配规则在 `lolita.md`，策略、应用授权、连续性和审计各有独立模板。`utils/wardrobe.py` 不依赖 Qt；衣装规则不送入艺术画风的八字段校验/压缩，也不占用 `config-styles.json` 中的画法字段。

本版采用文本衣装规则，不发送衣装参考图。新增目标不改变源图分析描述，也不自动改变画幅、画法参考、色调目标、发色、瞳色或年龄。普通 Lolita 规则没有旧内衣条目的年龄触发条件。规则是否在某模型上充分生效尚需在线验证。

分析提交时保存有效模板正文及 SHA-256，队列自动生图、历史生成重跑、GPT 断点及旧 `.request.json` 导入复用衣装快照。改变当前选择不影响已排队任务；直接点击生图使用当前衣装选择。重新分析历史时沿用该历史的衣装快照；没有衣装记录的历史按关闭处理。

GPT 身份审计传入衣装授权，保留非衣装身份门禁；不使用 `skip_identity_refine=true` 全局绕开身份。修手/身份修订护栏要求保住当前新衣装，不恢复旧服装。

gpt-image 专用页“生图/编辑后立即重绘”在启用衣装时采用重绘固件＋新衣装连续性约束，不把原生图文本（可能含旧校服）重新当作重绘指令发出去；衣装关闭时继续原行为。

分析页 GPT 完整流程和普通无头 GPT 全流程，在最终图确定后另做一次只读衣装审计。审计检查可见裙型/结构/装饰/协调/明确条件，缺字段、字符串布尔、明确失败、完全不可见和不确定均不冒充通过；不符合时保留候选与 JSON/TXT、阻断正常自动发布。GUI 成功联网响应按候选图、目标、实际文本及审计模板哈希缓存；失败续跑不重复生成已成功首图。

Gemini 生成和 gpt-image 专用页本版仅注入同一衣装目标与连续性指令，**没有新增自动衣装审计**，不能把成功返回图片解释为衣装符合度已审核。原手动选图发布入口仍是人工动作。

## 尚未实现的提取能力

本版新增的是独立衣装生成预设，未把「多图画风提取」直接改成服装提取。它的共性/对账/局部/终审/派生/比较框架可以复用，但各阶段提示词、衣装结果 schema、局部区域与衣装量表必须另建。不能把本版手写 Lolita 规则称为参考集训练结果。

现有旧 `cute-lingerie-wardrobe` 保留兼容，没有迁移或改写用户本地画风配置；请勿将它与新 Lolita 衣装同时作为目标。后续应在完成数据和通道验证后迁移旧条目。
