# Round3 衣装效果复核

本次复核以实际 31 张成功图片、15 对评分原文、人物卡和最终 prompt 为依据。用户已明确授权额外额度，本复核不将追加额度视为实验缺陷，不新增联网请求，不改生产规则。

结论：独立衣装方向有效，尤其是未指定服装的全身补全与 Gothic 换装。v4 没有证明全面优于 v3；应保留按授权分支的框架，并明确区分“原衣物加入 Lolita 元素”和“生成完整 Lolita 衣装”。当前近景评价不可靠，不能拿综合 failed 直接否定衣装方案。

## 评分的实际支持范围

原始 scores.json：15 对成功评分，每臂 15 张。clothing_action 两臂均 15 pass；identity_anchors 和 scene 同样全部 pass。它们支持基本文字条件的匹配，却不能证明 v4 的服装风格更强或更漂亮。

原始六项计数与 DS 报告一致：控制 83 pass / 7 fail，候选 81 pass / 9 fail；去 framing 后为 74/75 与 73/75。这是重复维度的描述计数，不是独立样本成功率，更不是 v4 优于 v3 的证据。

summary-v2.json 的 pass 7 / failed 8 / missing 1 采用四类必填字段，没把 person_count 和 scene 纳入最终必填聚合，因此 T02 Gemini 候选即使 person_count=fail，仍被汇总为 pass。报告的 aggregate verdict 不等于所有产品条件的最终门禁。本复核只指出其解释范围，未修改工具或评分。

近景共有 6 对、12 张图，不是 6 张；全部被评价模型判 framing=fail。CAL-CROP 已显示同一模型会把上胸图误读成腰腹，因此不能直接认定 12 张都失败。人工看原图时，GPT T05 的图没有明显腰腹，下缘接近上胸；衣物遮住解剖位置，严格是否超过 bust midpoint 应保留不确定，不能照模型的“lower torso”作事实。Gemini T05/T06 则确实明显更宽。两者应拆开报告，不能概括成“控制整体更紧、候选整体更松”。

T06 的授权是可见区域 REDESIGN，要求保留橙色、蓝鸟别针及位置；人物卡未要求保留 hoodie 类别。v3 换成衬衫不因这一点违反授权；v4 保留卫衣也不是预先登记的胜出条件。限制“只改可见区域”约束的是当前画面内容，不等同于“必须保留原衣物类别”。

## 面向产品的建议

继续使用独立 wardrobe，不合并进画法字段。保留 / 未指定补全 / 改款的路由很有价值，但让用户选 Lolita 时，应明确实际服装转换强度：

- **完整衣装方向**：未指定时补完整 Lolita；已有非 Lolita 服装且允许改款时，按 OP/JSK、裙体、腰线、领袖与鞋袜组织重设计，保留显式颜色和标志配饰。最贴近用户最初“角色本来不穿也偏向这个风格”的目标。
- **保留原衣物的融合方向**：明确保留卫衣/制服类别，只加可实现的领口、蕾丝、褶边等元素。效果可以好看，但应称带 Lolita 元素，不承诺完整时尚类别转换。
- **明确保留或只补全已有衣物**：不用完整目标设计块，避免把用户明确要求的衣物换掉。

子风格 sweet / classical / gothic 应作为衣装变量；颜色/配饰锚独立列出，避免用一个甜系默认模板把所有人物推向同一套粉色。近景只组织可见服装，不因要展示衣装而扩镜头；此时只能判断局部风格元素，不能验证整套 Lolita。

下一步优先级不是继续大规模 v3/v4 全套比较。先定“改款是否允许改变衣物类别”的产品语义；针对橙卫衣、工装、制服各做少量有重复的完整转化/原衣物融合比较。近景另用人工可验证的裁剪依据；右手持书、背景人数按独立条件复核。该建议不启动新实验、不部署 v4。
