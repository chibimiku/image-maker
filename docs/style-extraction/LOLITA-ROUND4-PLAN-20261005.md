# Round4：从参考素材到完整衣装转化

目标已确定：主要效果是完整转成 Lolita 衣装，允许重设计原衣物类别；明确的保留请求优先。古典、甜美、哥特先完成，中式、日式随后。

本文件是规划，当前只实施离线准备。上一轮用户授权的追加额度正常有效；本轮新素材与新实验不自动占用或继承 Round3 的预算，也不在此声明新预算已获批准。

## 一、先把范例变成可信证据

复用现有 inventory.json，原素材保持只读。每个主要系列目标筛出 8 张提取正例、3 张留出正例、3 张边界/反例，共 42 张；这是目标数量，找不到可信独立设计就标缺，不靠目录标签凑数。

8 张正例尽量跨至少 3 个画幅目录，任一画幅不超过 4 张。看清上身、腰部、裙体或可靠的组合视图；不要求所有配饰都可见。一个相同衣装设计的不同画面只算一个设计组，组内图片不能跨提取/留出。没有完全相同 SHA256 不能证明设计独立。

目录分类作初始线索，记录视觉确认的类别、可见结构、混合风格和不确定原因。边界例至少覆盖“只有颜色像”“泛用洋装/偶像衣装”“局部遮挡或跨类”。不要把古典酒红裙自动归哥特，或把所有粉裙归甜美。不要用幼态脸、身材、背景或画法定义衣装。

交付 selection.json、带 ID 图集、每张选入/留出/边界理由及原图 SHA256。seed ID（如 CLA08、SWE15、GOT10）仅作为待复核候选，不能当作预批准金标。

## 二、提取结构，形成三个独立衣装包

以 `prompts/wardrobe/reference-study/extract-wardrobe.md` 为基础，复用画风提取的清单、附件、批次缓存、对账与报告能力。每个系列 8 张，分成两个最多 4 图批次，初始最多 6 次视觉提取。批次须逐 ID 输出，不能只写一段泛泛风格摘要；漏 ID、错误标签和隐藏部件推测必须单独标出。

输出字段换成衣装专用字段：

- 上身类别与剪裁、领口/袖型、腰部连接、裙体轮廓及层次。
- 蕾丝、褶边、蝴蝶结的附着位置与节奏；面料图案及配套关系。
- 必要结构、可选变体、用户颜色锁优先级及不应迁移的人物/画法内容。
- 每条规则的支持 ID、独立设计组数、反例和置信度。

本轮操作性判据：欲作为“核心规则”的观察至少由 3 个提取组的独立设计支持，且需复核反例；不足则列可选或待确认。这是本轮筛选标准，不声称它是通用时尚定义。没有局部证据不能凭空补 OP/JSK 结构。

提取后锁定版本；每系列使用 3 张留出正例做独立核对，最多 3 次视觉验证。留出图不能提前进入总结 prompt、也不能看完再改成提取正例并继续声称留出验证。若其反馈导致规则修改，需注明留出已用于修订，后续结论不再称独立留出通过。

`reference-study/*.md` 是人写初稿，应保留并冻结为来源。新规则另存候选目录，并记录人工修订，不把人工初稿称自动提取产物。不做完整 1,372 张联网扫描。

## 三、先准备、审查实际生成请求

生成组装方式：固定人物和场景正文 + 完整转化授权 + 一个系列衣装包 + 被保护的颜色/配饰 + 全身构图。服装参考图只用于研究，本轮生成不发送这些图；可以直接检验提取文字能否迁移，减少复制范例人物与画法。

未指定衣服 → 生成完整衣装。已指定卫衣/工装/制服并允许完整改款 → 可改变类别和剪裁，保留显式颜色与配饰。明确保留、只补全已有完整服装 → 只用保留分支，不发送目标 Lolita 设计块。

检查 12 个转换提示词和 2 个保护提示词；保护提示词两通道相同。没有金标、样本 ID、评价说明或原图人物信息混入生成正文。模板 hash、完整请求 hash 和独立 run-dir 落盘。当前 CLI 有 Round3 特有的校验与评分字段，必须先检查并在现有同族工具中参数化，不要假装 planning.json 可直接执行；不要复制新实验脚本。

## 四、28 张初筛，分两波执行

统一虚构成年人物：32 岁、短深棕波浪发、灰绿眼、暖棕肤色、矩形黑眼镜、成年中等体型；固定自然站姿、双臂放松、不拿物件，素灰背景，只有一人，全身双脚可见。固定画法为 clean anime linework / soft cel shading，不从范例提取渲染风格。

| 输入情形 | 服装授权 | 颜色与配饰 | 系列数 |
|---|---|---|---:|
| U 未描述服装 | 完整补全 | 色彩由系列规则协调，无配饰要求 | 3 |
| H 橙色卫衣 | 完整转化，类别可变 | 橙色为主色，蓝鸟别针在人物左上胸 | 3 |
| W 藏蓝工装与灰裤 | 完整转化，类别可变 | 藏蓝为主色，铜叶别针在人物左上胸 | 3 |
| R 红制服 | 完整转化，类别可变 | 红色为主色，金星胸针在人物左上胸 | 3 |
| GP 红制服明确保留 | 不允许改款 | 衣物、颜色、金边及左翻领星胸针保留 | 不发送系列设计 |
| GF 工装只补全 | 已有整套衣物不变 | 藏蓝工装、赭色 T 恤、灰直裤及衣袋铜叶别针保留 | 不发送系列设计 |

每波 12 张转化 + 2 张保护 = 14 张。第一波 GPT；先看真实效果、定位候选缺陷，若要修订，保留原批次并重新声明版本，不将它和后续版本混成一个模型对照。第二波 Gemini 使用与第一波完全相同的冻结候选。如果第一波有系统性失败，第二波应暂缓并交付定位结果。

参数沿用 Round3 已记录的两通道冻结值，在计划里保留来源；无参考图、编辑、重绘、色调后处理或自动发布。主表每单元 n=1，属于早期筛查，不能宣称稳定成功率或因果优越；复测只针对明确不稳定的少量单元另行规划。暂时不跑近景，避免重复依赖未通过的纵向裁剪读数。

## 五、看效果的标准改变

首先回答“是否完整转化”，其次“是否像指定系列”。不能只使用 Round3 的 generic clothing_action=pass：它不足以区分普通洋装和 Lolita，或古典与甜美。

每张单独记录 pass / fail / uncertain / not_visible：

1. **完整转化**：对 U 有完整衣装；对 H/W/R 有实质服装类别与结构重设计，而非卫衣、工装或西装上仅加蕾丝。
2. **Lolita 衣装结构**：上身—腰部—有体积裙体的连贯设计及配套；不靠颜色或一个蝴蝶结。
3. **目标系列证据**：先描述具体衣物，做不含目标标签的古典/甜美/哥特/混合/不确定判断，再对照请求。混合并非一律失败，需说明请求的主系列是否清楚；不能以知道目标来倒推“像”。
4. **保护条件**：主色、指定配饰及左右位置，人物可见特征、人数、素背景、全身双脚。每项都纳入最终结果，不能出现 person_count=fail 却 overall=pass。
5. **成品可用性**：明显身体/衣物连接异常、胡乱蕾丝或配饰归属问题独立标注。外观好看不能抵消保护失败。

颜色、画法和年龄不可验证项各自说明。人工逐图复核是必需环节；自动评价不作为唯一裁决。先用实际人工标定正/反例校准完整转化与系列区分能力，模型读图失败则其字段标不可用，不为了完成报告把 uncertain 写成 pass。

初筛成功的可操作目标：每个系列至少 U 与两种已有服装表现出明显完整转化，保护例不发生换装；失败集中于个别条件时只处理该条件。不能将这一目标转换成统计显著或泛化成功声明。

首轮参考提取与测试只检验候选“有没有达到目标”，没有 A/B 对照，不能证明自动提取比人写草稿更好。若需要比较，后续挑 4 个固定单元，在同一通道用冻结人写版与候选版各重复 2 次，组成 16 张单独对照，而不叠加到本轮结果。

## 六、中式/日式与产品落地

主要三类问题收敛后，再从 chinese/japanese 各筛 8 张清晰结构正例和 3 张留出。新增 2 个衣装包，沿用共同完整转化授权。第一波先固定一个通道，用 U/H/W/R × 2 类 = 8 张，避免把文化融合与通道效果同时扩展。

判据额外要求：中式领襟/扣具或衣片与 Lolita 裙体相连；日式交叠领/宽袖/腰带与 Lolita 裙体相连。普通长直旗袍、普通和服或仅靠发髻/背景不算完整目标。两类可与 sweet/gothic 组合，但第一轮先测独立预设，不立即展开所有组合。

完成效果复核后再接入生产。保留独立 wardrobe 五个可选方向及完整转化/只补全/保留优先的语义；接入提交快照、历史重跑、身份衣物豁免与衣装最终审计。画法不修改。此阶段另做相关回归与 App 重启，当前不提前改 GUI。
