# 画风参考请求策略开发（2026-10-21）

用户授权修改开发及付费测试。本轮实现了可选的局部画风参考和请求一致性修正；随后获得向 new.aigc2d.com 上传指定原图及裁剪的明确授权，完成12图对照。未建立关闭脸部强化或增加局部参考的稳定画风优势。

## 已实现

- Gemini 带有效画风参考时，主要生产入口不再默认追加通用 `detailed face / clear facial features / sharp focus on face`。单图分析、单图调试保留已有画风 profile 的显式开关；无画风图或参考模式关闭时保留旧行为。后台避免重复追加同一后缀。
- `utils/style_reference.py` 统一创建局部参考：显式归一化矩形、原图 SHA-256、EXIF 转正、至少 32×32 原始像素、最多两块，角色为 `face_eyes`、`hair`、`material`。没有配置时不自动定位、不附加图片；缓存内容被改动会重新生成。
- `build_ref_gen_params` 的三元组契约不变。Gemini 原画风全图先提交，局部图随后，图后使用明确图号替换单图“immediately above”声明。GPT 首图与独立 GPT Tab 使用“内容图→局部参考→画风全图”，全图保持最后。显式角色图号与图片数组一致，超过 GPT 16 图上限发前拒绝。
- 单图调试的手动画风图现在在组装前生效；换成另一张图时不复用旧局部区域。Gemini 内容附件与画风附件按真实顺序声明角色，解析出的内容锚同时用于实际正文和图后约束。GPT 调试参考模式关闭时不再仍然附上预设画风图。
- GPT 页面显示新增局部图编号，修正全图缩略图编号、正文图片引用、自动顺延及素材数量上限。
- 单图分析的 GPT 生成 manifest 增加参考角色、原文件 hash、GPT multipart 编码口径的传输 hash、转正尺寸及裁剪配置。小图按原文件、大图复用后端的压缩函数计算；Gemini 测试另记录其 JPEG 编码口径，两个通道不会混用传输 hash。
- Gemini JPEG 编码在发送前应用 EXIF 方向，避免全图和局部图使用不同方向。
- 既有画风同步工具支持新增局部参考字段；本轮未执行画风库同步或修改任何画风条目。

## 使用

正常重启 App 后，在“单图调试→编辑样式”中选择参考全图，用“框选区域”标注脸眼、头发或材质，勾选“附加局部画风参考”并保存。使用头部插入、参考优先或图文交错时附加这些局部图；关闭参考模式时不附加。增加局部图会增加输入费用。

更换参考全图、原文件内容变化或区域无效时，需重新框选；不会自动猜测新区域。框选仅生成参考附件，不裁切重绘或贴回成品。此功能默认未启用在任何现有画风上。

## 官方依据与限制

- [OpenAI Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)：为参考图分配明确用途，单独描述新主体；支持用输入图迁移视觉风格。
- [OpenAI Image generation](https://developers.openai.com/api/docs/guides/image-generation)：有图可通过 edits 生成新图；Responses 支持多轮上下文，但会改写 prompt。
- [Google image generation](https://ai.google.dev/gemini-api/docs/image-generation)：支持多参考图，Pro 列有最多三张画风参考；多轮对话是推荐的迭代方式。官方没有证明“交错一定比其他输入顺序更像参考图”。
- [Google GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)：真正的历史多轮请求需要保留 thought signatures。现有单轮生成链没有伪装为完整多轮。

全图＋局部图属于待验证方案。没有增加自动画风校正或改变 refine 保真门禁；是否值得额外校正，要在首图对照可看后决定。

## 明确上传授权后的12图复验

用户先选择仅离线验证，之后再次提出付费测试；因自动审批要求明确覆盖此前被拒绝的目的地和图片，用户最终逐字确认：将 ha9siro、さくらしおり参考原图及脸眼裁剪上传至 `new.aigc2d.com`，最多12张，可以自动重试。实际运行仍关闭自动重试以保持总尝试上限。

使用已准备的两份 `*-network-r2.json`：每种画风 A/B/C 各两张，共12次图片请求、12图全返回、0失败、0重试、0额外文本调用。六个预算槽/画风全部结算，无在途。12文件及12解码hash唯一，均1696×2528。模型配置和返回的 `modelVersion` 均为 `gemini-3-pro-image-preview`；没有据此验证供应商内部模型实现。

12份请求回放逐个核对：A/B真正发送1张完整画风图，C发送全图＋原图hash绑定的脸眼裁剪；实际Base64解码hash与记录的传输hash一致，实际文字parts也与保存的assembled_text一致。没有仅把路径写入文字或无图请求的情况。

逐张实际查看了12张全图、12个脸眼审阅裁剪和两种实际参考裁剪。观察存 `manual-review.json`；没有新增付费评分或将主观结论冒充模型/深度指标分数。

| 条件 | 结果 |
|---|---|
| A 原强化 | ha9siro两张已有碎晶亮点、发丝彩光，但仍缺原参考的高频虹膜；さくらしおり第二张明显趋向通用大圆高光/简单渐变 |

结论：局部参考继续保持可选，未给任何已有画风默认启用。关闭通用脸部强化也未在本样本中建立一致优势；此前的默认代码选择不能据本轮实测包装成画风改进。更多星点、光晕、书封金纹或背景玻璃片不等同于画风更接近。

限制：每条件仅两次独立采样、没有固定seed；C同时新增图片并把单图图后声明替换为明确图号的角色说明，因此只能比较完整请求包，不能独立归因于裁剪像素。仅覆盖Gemini Pro首图，没有线上测试GPT、refine、整链或完整多轮上下文。全图人工检查不代表完整人体审计或用户验收。
