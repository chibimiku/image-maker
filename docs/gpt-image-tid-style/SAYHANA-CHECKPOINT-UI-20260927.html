2. 优化判断

仅 say-hana-v4 当前启用，其余四个版本停用；五个版本却共享同一张旧参考图。当前 v4 的 prompt_gpt 强调“long narrow almond geometry”，重绘条款又要求“rounded almonds … rather than a slit”，眼形目标相互冲突。此外现用 v4 主张均匀装饰光、少光泽，而近作中的边光、体积、头发反射较明显。

建议：先统一 v4 的圆杏眼语法，保留其橙绿装饰重彩定位；近作厚涂/彩色边光另设受控实验分支。首轮对照用当前图、145613681 清洁角色区域、138796681 全身区域三组，保持内容锚、提示词长度和模式一致；同时检查相似度与主题/发色/服装泄露。不能仅凭目视判定替换后会提高生成分数，因此本轮不直接替换正式配置。

3. 失败原因与恢复

日志有代理断连、图片提取失败及分析 JSON 解析失败，不能将重试日志条数直接当失败率。代码层更明确的问题是：后处理返回 partial 或审计异常后，原来仍可能标成功。现改为失败工序标红，保留成功图片和请求快照。

  1. 在历史队列右键 → “工序断点 / Gemini 重绘” → “从断点续跑”。复用已完成 GPT 首图和工序产物，后处理内部也从失败步骤继续。
  2. “从 GPT 首图重新 Gemini 重绘”：新建重绘尝试，保留原尝试，不再次调用 GPT。
  3. “重绘当前图”：输入人体、腿长、姿势等具体修正要求；源图单参考，锁定源图宽高比，不再强行叠加会抵触姿势修正的通用渲染锁。保留未指定部分，且不对 Q 版施加统一头身比。
  4. 重启后可在队列空白处右键“导入工序断点 / 旧首图请求”，选择 generation-checkpoint*.json；旧首图的 .request.json 也可导入。旧快照缺失的画风门禁开关/条款按当前配置恢复，日志明确提醒；旧任务若没有首图不能恢复不存在的首图。

每个新任务在过程目录保存断点；质量与身份门禁内部缓存每次成功联网操作，若修订图已出而复审失败，续跑只补复审。文件被移动/删除时，失效工序及其下游不再复用。取消/失败不删除已有图片。工序中断与图片视觉错误分开：能成功出图仍不等于人体一定正确。

4. UI 与验证

分析 / 停止 / 批量改一行三按钮；分析后两个生图勾选项与仅保存项改为一行；原始生图 / 优化生图 / 停止生图与倒计时合并一行。默认 1100×750 下队列、日志各保留约 141px，窗口增高仍优先给队列/日志，GPT 参数仍是两行。

新增回归覆盖：重绘失败续跑不重复 GPT、质量修订成功但复审失败不重复出图、文件失效重算、partial 不假成功、旧请求导入、人工重绘失败后复用相同输入与工序目录。修改 Python 后必须重启 app 才能使用新功能；请先等待正在运行的任务退出。

5. 后续：tinkle

验证结果：全套 481 项测试通过，1 条既有服饰采集后台线程在窗口销毁后回调的警告；本轮新增功能均以模拟接口验证，未声称已做收费接口实测。两项 SD UI 测试改用临时配置，避免写真实用户配置。

按用户要求排在本轮之后：分开研究“材质半透明/透光层次”和“轻度 Lolita 设计授权”。半透明优先作用于欧根纱、薄纱、蕾丝、丝带边缘、发丝与透光叠层，不把人物皮肤或整件服装泛化成透明；蕾丝与蝴蝶结为少量可选点缀，保持身份、主色、主体衣装结构。必须同步检查首图、重绘与身份门禁，避免新增点缀被身份回改撤销。本轮未修改 tinkle 配置。
