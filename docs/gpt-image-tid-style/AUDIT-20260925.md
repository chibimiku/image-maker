## 2. 当前流程发生了哪些变化

1. **内容变了、复杂度变了。** 指定照片既有分析 JSON 的优化描述有 4406 字符；它同时加入了服装细节、动态姿势以及 `luminous pastel luxury` 等画法描述。这个步骤并非纯粹忠实转录照片。GUI 实际使用哪个版本，取决于原始/优化按钮对应的文本。
2. **首图组装变了。** 当前是 `prompt_gpt` + 内容描述 + 排除句 + 派生渲染条款，总长 say-hana 6871、noir 6799 字符。历史 V6 是 2553 字符的另一套结构。内容与画法可能相互牵制；本轮没有证明“字数”是独立根因。
3. **请求端点变了。** 历史走 edits，GUI 默认走 generations 并附中转站扩展的 `image` 字段。不能仅凭端点名字断言参考图会或不会被当作角色来源。
4. **重绘输入变了。** 旧满意作品只重绘首图；后来的默认配方再次加入完整画风角色图、范围指令与画风条款。身份锁能降低风险，不能保证第二张图的内容绝不进入结果。
5. **默认附加了多个后处理。** 调色、加墨与结构线会改变图像；全局亮度/饱和度接近参考图，并不代表笔触、线条、材质和人物设计都更好。

## 4. 已落地的改动

- 单图分析 Tab 配方升级到 v4：默认只启用 Gemini 单图保守重绘；范围 `full`（仍有身份锁）；结构线、局部贴回、调色、加墨默认关闭。首图继续 high、按输入比例选尺寸、generations 默认。
- 画风参考图只参与 GPT 首图。重绘 `reference_mode=none`；后端也不会再对缺席的第二张图追加角色分工或 STYLE LANGUAGE 条款。本地可选调色仍可读取参考图。
- 日常只显示重绘开关、“高级选项”和“恢复推荐”；参数区默认折叠，展开后仍是两行。队列/日志保持固定区，拖图落点不变。删除了“首图直接用分析原图”这个仅保存状态、没有进入实际生成分支的死开关；四区链改标“实验”。
- 首图旁保存 `.request.json`：实际组装文本、参考图路径及 SHA256、请求模式、质量、尺寸、工序、固件文本、最终输出路径。不保存 API 配置和密钥。
- 无头工具修复 `style_entry` 未定义错误，默认内容字段改为 `english_description`；增加独立输出目录、预检、已有首图复测、完整 prompt 快照、重复次数。默认后处理与 GUI 一样只做单图重绘。使用 `--content-field` 可明确复测历史内容字段。
- 修复重绘接口忽略 `final_dir/work_dir` 的落盘问题，实验不会绕出隔离目录。
- 离线测试清理通用 API 密钥别名，避免开发机环境污染断言。
