## 结论

### 1. 当前修线默认应继续用 v5 + 仅源图

它把平均段长从 80.8 提到 103.1（约 +27.6%），端点密度从 33.51 降到 26.84（约 -19.9%），三次的色彩和角色都较稳定。v4 与 v5 很接近，但没有稳定优势；v5 对不可见肢体、眼睛和含混结构的限制更完整，仍适合作为默认固件。

### 2. 画风文字本身可以帮助连线，且比再次发送人物参考图安全

“仅画风条款”组的平均段长最高，为 107.5，已经复现历史优秀完整重绘 107.4 的量级；端点密度 27.33，略逊于 v5 仅源图和历史单样本。它没有把整幅图强行转成蓝青高饱和，也没有把参考角色的脸直接带入。

这说明可把画风条款拆成两类：线条/材质语言可用于重绘；具体调色板、眼睛、服装装饰语言不宜用于保守修复。当前 19 条条款仍混有 sapphire、turquoise、rose pink 等明确颜色，个别结果出现蓝色胸针/装饰变化，后续应再做一版“只保留笔触、边缘、材质和线条组织”的无配色条款。

### 3. 人物画风图单独使用仍有角色泄漏，而且是随机风险

“仅原始人物画风图”三次中有一次明显把参考图的绿色虹膜和头部花饰带入源角色。另两次较接近源图，说明身份锁降低了风险，但没有消除风险。不能用三次中的成功样本宣称问题已经解决。

### 4. 画风图与画风文字同时使用会协同放大风格，也会伤害修线和身份稳定性

两者同时使用时，饱和度从约 77 升到 112，画面明显转为参考图的蓝青色；绿色/青绿色眼睛也在样本中出现。与此同时，段长降到 99.8、端点密度升到 28.36，修线指标反而弱于仅源图和仅文字。

因此这不是“文字导致”或“图片导致”的简单单因素问题：单独使用两者时影响较温和，组合后出现明显协同放大。需要强风格迁移时可以把它作为显式高级模式，不能作为保守重绘默认值。

### 5. 无人物风格板能减少脸部角色特征泄漏，但不是修线最优解

三次风格板结果没有复现原人物参考的绿色虹膜和脸型搬运，说明去掉完整人物确实有效。不过它仍把服装和环境明显推向蓝青色，端点密度 28.73 是本轮最差。该风格板来自原图的蓝色头发、缎带和服装局部，所以仍携带具体配色与服饰材料偏置。

如果要继续走风格板路线，应生成更抽象的板：只保留笔触样本、边缘阶梯、材质纹理和明暗块，不保留头发、蝴蝶结、蕾丝服装等可识别物件。

## 推荐参数

GUI 默认保持：

```text
model = gemini-3-pro-image-preview
resolution = 2K
aspect_ratio = 跟随源图（本样本为 2:3）
firmware = repaint-system-conservative-v5.md
scope = full
reference_mode = none
detail_suffix = false
```

高级选项可增加一个实验预设：

```text
“线条/材质语言增强”：v5 + 仅渲染条款，不发送第二张画风图
```

现有“画风图 + 画风条款”应标为强风格重绘，并提示可能改变虹膜、饰品和配色。

## 工程修复

实验首轮发现 Gemini 有时以 `fileData.fileUri` 返回图片，旧后端只识别 `inlineData`，会把有效结果判为失败。后端现已支持两种结构并新增回归测试。同时屏蔽了可达数 MB 的 `thoughtSignature` 日志内容，避免单次响应淹没日志。
