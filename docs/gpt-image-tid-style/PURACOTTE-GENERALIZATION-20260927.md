## 两个 case 的阶段证据

### 4660b20c

过程目录：`data/20260927/analysis-gpt-image/4660b20c-puracotte-style-v2-170654-ede544/`。

旧 `refine-quality-audit-1.json` 已报 major，明确指出动作、两臂、腿方向、机械结构、背景和画风均漂移。旧流程没有使用这份复审阻止后续工序。身份回改只把发色/发型、眼色和衣装等改回正确，无法恢复原姿势与 puracotte 画法，却被当作全链完成。

新最终复核在线调用成功：[原始审计](puracotte-audit-20260927/4660b20c-final-audit.json)。判定 `needs_refine=true, severity=major`；检出站姿替代腾空、动作及支撑点丢失、平面填色和均匀重轮廓偏离参考图的层叠色彩与细线层级。新流程会禁止发布这张候选。

## 改动与边界

1. `hands` 保留旧 API/断点名称，升级为逐角色人体拓扑检查；全图、3×3细节图、两张有重叠的连续下半身视图共同审计，不重复计数同一条腿。不要求隐藏肢体可见，不添加通用成人比例。
2. 明确缺陷最多两轮 source-only Gemini 定点修订；肢体归属不确定转人工复核；GPT-only/关闭重绘时只审计并标红，不强制重绘。
3. 质量修订后的重大漂移或明确背景漂移立即失败，禁止继续靠修身份“洗成成功”。局部残留可以进入后续人体修订，但最终复核通过前不能发布。
4. 身份/质量/人体修订带渲染文字护栏，只提取 Lighting/Brushwork/Edges/Texture/Detail/Avoid，不追加参考图角色、画风配色或固定留白构图。保持各自墨色、水彩、Q 版或 3D 画法。
5. 最后一次模型修改及本地收尾之后再检查实际成品结构、姿势/场景、画风和局部明暗可读性。高调画风本身不判失败，也不以全图平均亮度强制降曝光。
6. v3 人体门禁升级旧断点时失效自身和下游发布缓存，保留上游图、原尝试和收费调用缓存。显式从 GPT 首图重绘的新尝试取当前画风条款；普通续跑仍忠实保留旧快照。人工修正以人工输入当前图/要求为姿势锚，不用旧 GPT 姿势抵消授权改动。
7. puracotte 的短版说明去掉固定半幅留白和过度强调平面 cel，改为层叠色彩/柔和渐变、细有色线、选择性珠光、保留深色固有色及源场景密度。仅定向同步 puracotte 和 Sheya 修改到画风子模块，未提交其他工作。
8. CLI 也增加人体与最终审计；未通过/审计失败返回非零并保留候选，不发布。GUI 可自动做两轮结构修订，CLI 本轮只加最终验证及文字护栏。

额外工序增加视觉文本审计调用；无缺陷时通常增加人体与最终复核两次，发现明确结构问题时最多增加两次图片修订。成功调用续跑复用，不能保证模型不漏判，也不能保证每次局部修订都保住画风。

## 验证

系统 Python 无 pytest 包，未运行完整 pytest。以临时测试桩逐个执行 `tests/test_generation_checkpoint.py` 与 `tests/test_refine_quality.py` 的 21 个测试函数，全部断言通过；覆盖重大质量漂移拦截、旧发布缓存失效、跳过质量回改仍检查人体、GPT-only 不强制重绘、审计超时后复用收费图、结构不确定转人工、未授权身份差异拦截和无效 JSON 拒绝。语法/导入及联网工序超时预算也验证。

另执行 6 个 GUI 回归函数，验证新增工序预算、局部 2K、窗口拉伸分配、紧凑布局、source-only 与跳过重绘设置，全部断言通过。身份回改未获授权跳过时，复审差异/人工复核也阻止发布；CLI 质量重大漂移会立即停止，不继续收费修身份。

在线调用使用用户明确授权的现有接口：三次初版审计成功；增强连续裁剪版本遇到三次 503。无新增图片生成调用，原图未覆盖。修改 Python 和画风配置后需要重启 app。
