# 书籍色板与自动规则接入（2026-10-07）

用户恢复额度后要求继续研究，并指出 UI 调整繁琐：希望选择与书中一致的三十多种配色，规则能够自动生成。本轮优先补齐现有使用入口，未启动新的收费生图实验，未重启现有 app。

## 可以怎么用

在「提示词生成」或「gpt-image-2」直接生成入口填写正文，选择配色方案，点「规则」→「自动生成规则」→查看建议→「应用规则」。之后按原有生图按钮生成。也可以直接打开规则窗口，不选方案时从书籍目录自动推荐。

- 下拉接入已提取的 **31 套书籍案例、155 个色格**；另保留原来 3 个实验预设并明确标注。31 是当前目录数量，不表示整本书所有配色已经抽完。
- 选定方案后，自动生成只能使用该方案；不能偷偷换一套色板。
- 自动填写已有区域、色调和宽松主次关系，可直接查看后应用，也可微调。不要求逐项先填完才能自动生成。
- 提示词生成入口以第一张非空提示词卡片作为建议正文；还没有卡片时用输入关键词。批量中的每张实际正文仍独立检查落点，缺失就报错；不要将第一张的区域规则无条件套给不同内容。
- gpt-image-2 入口使用当前正文。若请求期间或应用之前正文改变，旧建议会被拦住。
- 自动生成只在点击时调用现有文本 API，成功结果缓存；不生成图片，不自动进行二次重试。按钮执行期间窗口不会销毁线程，失败仍保留手动填写。
- 配色默认关闭。仍限无参考图、无编辑/重绘/后处理的文字首图；图片分析 refine 的情绪/季节选择维持原有独立逻辑。

## 与原书保持一致的含义

消费 `prompts/color-knowledge/book-palette-catalog-v1.json` 的原始案例 ID、五色色名、顺序、作者和 PDF 页码，未改目录。颜色编号仅用于定位色格，不能当成主次排名。

目录中只有部分扫描实测色值，另有标称值或仅色名。界面区分来源，缺失 HEX 保持缺失，不补猜；生成约束采用原有色名，不宣称精确 RGB 复现。没有合适落点的颜色可以不使用，不为用满五色新增物件。

原书未注明主次的方案，其角色字段仍保持 `null`。自动填写的主色/辅助/强调是**针对本次正文的建议**，快照明确记录 `role_source=user_or_model_task_proposal_not_book_order`。仅当用户应用时进入任务，不写回原书知识库。宽松主次不写精确百分比，不改变物件尺寸、构图或天气；书中具体案例/室内比例不推广为插画标准。

生成建议只返回目录中的 ID、颜色编号、已有区域和规则 ID。自造 HEX、自带最终 prompt、权限字段等不被信任。编译前检查色板锁定、颜色存在且不重复、落点存在且不重复、主次角色完整；原有文字/参考图/后处理边界仍检查。

## 修复恢复交接中的两项证据问题

1. `api_backend._generate_request_replay` 保存完整脱敏请求，不再对正文使用 4000 字符日志缩略函数；长正文末尾保留，凭据脱敏，不改变实际传输输入。历史缺失回放不补造，不补图。
2. `color_direction_pack` 的报告预算、授权追加和评审标题读取当轮数据，移除旧 S1-A 崩溃原因及“四组”标题。历史报告保持原样，v3 仍以独立复核勘误为准。

历史冻结包包含源码 hash；此次 `utils/theme_color.py` 更新后，原包离线核验应提示来源变化，不能把它报告成新代码下全部通过。原三预设的冻结 plan/prompt 仍逐字复算一致。对应测试现在分别核对源码变化、原槽位条款以及新编译时的真实源码 hash，未修改历史 pack、预算登记或 hash。

## 验证与限度

相关 7 个测试模块共 **87 项通过**：31 套编译、原预设及历史槽位兼容、锁定方案、非法/缺失落点、主次角色要求、缓存、异步按钮、正文变化、应用/取消及配置恢复、长正文回放与实际预算。6 个修改后的 Python 模块编译检查通过。测试使用临时目录，无真实生成请求。

规则弹窗在离线 Qt 环境截图查看，680×600，五色表格、自动生成按钮、预览及应用按钮均可见。中文字体仅在截图进程加载 Windows 微软雅黑，没有修改系统或 app 全局字体设置。截图：`data/test-result/20261007/theme-color-ui/book-auto-rules.png`。这是模拟建议填充后的布局验证，不是线上模型生成结果。

尚未验证：现有文本端点实际返回建议的合格率、31 套书籍色板实图执行率、不同正文批量稳定性、与参考画风/后处理的共存。当前代码接线不等于二阶段效果验收。按用户此前“任务正在运行，暂不重启”的要求，本轮未重启；空闲重启后 GUI 才加载新版。
