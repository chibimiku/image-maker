### 主体与颜色授权

建议保留春日河畔单人钓鱼主题，但新建中性色主体协议：中性银灰发、象牙白连衣裙、深中性色厚底鞋；既有腰带和鞋蝴蝶结允许按色板改色。不得沿用“粉色鞋/粉色蝴蝶结不可变”同时又要求这些部位变红的矛盾协议。

主体、服装结构、物件、动作、画法和画幅在所有组保持一致。新增色彩只作用于已有区域，不通过增加红色道具、第二个人或改变时间/天气来达成。鞋与腰带点缀必须在构图中可见，否则区域执行判为不可验证，不能计成功。

这套中性色主体是新的诊断用例，不与旧粉发主题直接作配对比较。后续还需单独测试既有角色固有色与环境色板的兼容。

### 两种条款的公平性

- 简洁版：明确颜色、主次和区域分配，并保留同一保护条款。
- 知识编译版：同一色板、区域和授权，增加有来源的明度/彩度层级、色彩关系说明。
- 不让知识版额外改变物件、构图、光照时间或画法；两版均需完整表达同一目标，不以删掉简洁版的关键约束制造优势。
- 编译结果离线冻结，记录知识来源、最终 prompt、hash 和长度，不在每次重复时随机重新选方案。

每张方案卡必须写明主色/辅色/点缀色、允许中性色、允许变化区域、保护区域、适用范围及排除项。肤色、象牙白、正常阴影与高光允许存在；固定色板不是“全图只能有两个 RGB 值”。近似 HEX 仅作可视化参照，不作为未经校准的逐像素硬门禁。

## 4. 执行与预检

复用 `tools/color_knowledge.py` 和 `utils/color_experiment.py`；新协议放 `prompts/color-knowledge/`，新产物放 `data/test-result/<日期>/color-fixed-palette-v1/`。不新增一次性脚本，不覆盖旧请求或旧判断。

首轮使用 Gemini 直接生成，模型/节点从配置解析并记录实际值；同批参数一致，建议沿用旧试验 1K、3:2。不附源图或画风图，不重绘，不做色调校准或本地后处理。若配置模型与旧批不同，明确标记为新模型实验，不宣称可直接对比。

离线预检交付：

- 7 组（或明确缩减为 3 组）的最终请求预览、颜色冲突检查和对象增删检查。
- 生成数量、实际请求重试上限、评审数量及费用估算。21 张是计划产物数量，不是请求次数上限；收费前需明确后者。
- 成功产物续跑复用；失败、拒绝和不可验证保留，不为凑成功率替换样本。连续两次请求失败停止并报告。
- 评审建议按每组 3 张全图共 7 次；额外最多 2 次仅用于预先约定的失败恢复/证据不足，不反复询问直到给出满意评价。9 张缩减版对应 3 次评审，额外预算另列。
- 回归测试使用 `tmp_path` 或复制的请求夹具。现有恢复测试涉及真实 reassessment-v2 目录，应先隔离，避免测试重写已交付报告的依据。

## 5. 验收与交付

逐张分开记录：颜色组合符合度、区域分配、额外显著色块、保护颜色、主体/物件内容、画法观察、证据位置和不可验证原因。画法观察不是画质打分，也不能靠同组相似证明相对基线画法未变。

汇总至少包含两个不同指标：

1. 配色执行：conform / partial / fail / unverifiable 的逐张数量。
2. 可用候选：配色 conform 且没有明确保护色/内容违约的数量。

探索性晋级条件：一个版本 3/3 配色符合，且无明确保护色或内容违约，可进入工序保留试验；2/3 不能称为已稳定实现。3/3 也不是跨主题、跨模型的普遍可靠性证明。若没有组晋级，依据失败区域调整条款，再提独立小批次预算。

保留原始模型响应与人工裁决两个层次；文字“无法确认”不能一律消除同条中的明确内容缺陷。T3 一类“主导”与“排他”要求必须在协议里区分。交付结构化逐张/汇总/协议、离线内嵌全图页、请求与原始响应以及真实调用账本。

## 6. 晋级后的顺序

先做小规模重绘保留，再接生产入口，不自动串行执行。

- 从一个晋级配色中按既定顺序取最早两张可用图，不按美感挑图。
- 选同一画风，分“现有重绘”与“显式传递配色合同的重绘”两支，共建议 4 张；单独预检与确认预算。
- 检查色板、区域分配和保护色是否继承，并与对应首图比较；画风参考的颜色泄漏必须记录。
- 如现有身份保护条款与授权改色冲突，先说明冲突和拟议规则，不通过关闭身份/质量门禁掩盖问题。
- 通过后做独立于画风的配色选择原型：人工选择优先，LLM 只能从许可集合选择，固化配色合同并纳入工序快照/缓存失效依据。
- GPT 通道恢复后独立复验，不为等待 GPT 阻塞 Gemini 的首轮验证。
