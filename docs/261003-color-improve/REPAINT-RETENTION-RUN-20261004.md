## 6. 执行期发现的缺陷与修正（都已修，并留档）

1. **模型与 api_type 只写在快照里**：`assemble_repaint_request` 的 `call_kwargs` 不含 `model`/`api_type`，真正发送时靠 `gpt-image-optimize/config.json` 兜底。实验层现在把冻结值显式写进 `call_kwargs`，预检再用 `resolve_repaint_call` 逐条复核（四条全部一致），**生产 dispatcher 默认行为未改**。
2. **实验层重复预留**：后端 `generate_image_repaint` 内部已经为每次请求预留，实验层又预留一次，撞上「同一 run_id 只允许派发一次」的保护，导致前 13 次尝试全部被本地拒绝（0 次 HTTP）。已删除外层预留，改为「发送前检查剩余额度 + 让后端完成唯一一次预留」。
3. **产物路径落在真实日期目录**：`save_sub_dir` 是相对路径，后端按当前工作目录解析，产物一度落到 `data/20261004/pipeline-steps/`（真实产出目录）。已把四张候选**移动**进实验目录（原路径写进 `original_output_paths` 留档），并把实验层的路径解析改成按仓库根解析，后续运行不会再落到真实目录。
4. **测试隔离**：重评回收用例原本会在 `data/test-result/20261004/` 下建临时目录；现在改为在带随机后缀的探针目录里做、结束即清理，并断言交付记录的 mtime 未被改写。
