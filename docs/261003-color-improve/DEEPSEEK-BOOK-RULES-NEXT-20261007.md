## A. 自动规则的真实入口验证

使用 utils.theme_color_rules.generate_theme_rules 与现有两个 UI 入口，不能复制编译公式或另做一套推荐流程。准备三份正文：已有环境大表面+小点缀、有两个可比大面积表面、具有明确头发/眼睛/植物固有色。正文不添加风格参考图，不开启后处理。

每份正文分别计划测试“固定书籍案例”和“未选自动推荐”。固定方案必须仍为原 ID；未选只能推荐31套书籍案例。每个建议检查：色名/编号属于原方案，区域字面存在，无新增物件，无按五色顺序推主次，无精确面积要求，无越权改固有色；未适用颜色允许不用。失败不能自动补请求，以失败原文和类别落盘。单次成功缓存复用必须零额外发送。先用打桩运行验证落盘，真实文本请求预算提报为最多6次、关闭自行重试，不要泄露凭据。

检查 UI 的异步按钮、正文变化拦截、手动微调、取消不改变原选择、应用后快照，以及不同批量正文的落点校验。推荐合理性与结构校验合格分别报告；不能用结构通过代替人工合理性结论。

## B. 宽松主次关系实验准备

准备两个场景，各自原本就有两个可比的较大表面和一个小点缀。使用两套来源明确的书籍案例，记录PDF页码、五色色名及来源。主次角色为本次设计提案，不写入原书事实。正文不含与主次目标矛盾的硬比例。

每个场景冻结三个条件：A未指定主次、B主色主导/少量强调、C两色并重。A/B/C色板、具体落点、主体、构图、画风、画幅、模型和参数完全相同；tone关闭，只有主次规则变化。建议重复两次，共12个图像发送槽位，评审4组。这个数量仅为预算提案，用户可批准缩减；未授权不能发。若缩减，执行前一次性冻结，不得看到分数后删样本。

共享当前编译器生成 prompt，先完成离线核验与请求预演。旧实验 pack 的源码变化必须如实报告，不改旧 hash 换取通过。新协议与预算要独立登记，不能借旧 APPROVED_PACKS 额度；技术超时计入发送预算，未知提交先查证，不自行补发；不以效果不佳重画替换。

评审分别记录：每个绑定表面是否使用指定颜色、保留固有色/内容事实、主次是否朝目标方向、该颜色是否足够可见、跨图几何/面积变化是否造成混杂。允许“不确定”；不把一切构图差异当单图内容失败，也不全部降为轻微轮廓差异。目标是宽松视觉关系，不能用精确像素百分比作硬门槛。两色并重按可见份量判断，不要求两个RGB掩膜面积相等。

同一成功输出为主结果，失败/超时/缺评审都保留。报告方向观察、单图合规、完整可比对照三个分母，列出实际发送次数、所有原文请求末尾、授权追加、缓存命中、源码与数据hash。人工确认项不得由模型冒充。
