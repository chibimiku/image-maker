## 第一阶段：主题色板选择与首图生成

问题：用户选一套颜色，能否将颜色分工清楚地送入现有生成流程，并保存实际使用的方案？本阶段固化的是消费与记录流程，不把模型执行成功率固化成保证。

首版落地到“批量提示词/生图”和“gpt-image 专用页”两个直接生成入口：默认关闭，共享三组试用组合；允许指定正文已有环境与小点缀物件，提供显式 LLM 闭集推荐。首图保存条款、hash、模型、区域、请求及产图记录。开启配色时不接参考图/编辑/重绘和确定性后处理，避免混淆第一阶段与保留研究。GPT 可试用，但效果不继承 Gemini 的实验成绩。

全书色板目录继续作为溯源和扩展资产保留；未明确主次的条目不按排列顺序自动晋级为“一键生图方案”。三个试用组合也不是从书中直接测得的三套配色，色板预览属于设计近似值。

使用与实施见 `FIRST-STAGE-APP-20261005.md`。本轮不新增收费模型测试，不修改源图分析真值、画风存储或生产审计门禁。手选色板不是“改善画质”开关。

## 第二阶段：色调规则＋主次面积规则的宽松提示词组织

问题：同一固定色板，怎样表达明亮、深沉、清浊、主次与视觉面积，从而得到更清楚的颜色组织？**不要求精确上色、像素 HEX、严格蒙版或逐像素面积统计。** 也不以首图超出某个色值误差阈值作为失败。

### 先整理三层数据

1. **色板层**：保持颜色组合与来源。继续盘点教学页和案例页覆盖；为重复引用建立 canonical_id 与 aliases/source_refs。已确认 PDF 74/147 同图只计一次，不能再称这项尚未完成。相同情绪标签不同位置/色格不自动去重，相近 HEX 不直接合并。保留无色值和来源记录计数。
2. **色调层**：消费已有 12 类简化 NCD，不再重复提取一套。先按原描述提供少量清楚的选项（沿用/明亮清色/柔和浊色/深沉等），保留到原 NCD 条目的映射与适配来源；不虚构 HSV 阈值。不把“深沉”写成夜晚、阴天、悲伤人物，也不把“清色”写成另一套色板。混合色调的色板允许主色柔和而强调色保彩度，不强行全图同一色调。
3. **主次与面积层**：分别存原书已明确的 role/relationship、案例专用比值、工程适配。未指定就是 null，不从五色顺序推断。生成侧先用“大面积主色 / 中等辅助 / 小面积强调”；另可显式选择两个色系视觉面积接近。面积针对颜色的视觉组织，不要求扩大物件或改构图。

### 编译规则及优先级

组合为 `选定色板 → 色调选项 → 主次/面积组织 → 原内容和画法保护`。用户明确的色板与颜色分工优先；情绪、季节、意象只做检索标签或说明，不暗中换色。已有本体色、人数、布局和对象继续保持。新规则不改变天气、时间、人物心理或画风，也不加物件满足强调面积。

PDF 59 的 7:3、9:1、9.5:0.5 是各自基调:强调的案例比较，不是全图通用百分比。PDF 77 的室内比例只留在显式室内且用户选择相应模式的分支，默认不编译。大多数插画只输出定性面积关系。PDF 18–19 的渐变/分离可作为后续可选组织提示，不添加渐变背景或强行描边。

### 建议的小范围验证

从现有较一致的 P1 入手，用两个已有不同主题，保持色板、既有区域、内容、模型和尺寸；分别比较“只有色板”“色板＋明亮/柔和色调”“色板＋深沉色调”“色板＋主次/面积关系”。先分别测试色调与面积，避免把多种变化混成一个包；每个小组两次只是探索。具体请求数、预算和主题在新协议中提前冻结；此路线本身不授权或启动收费测试。

宽松评价只回答：主色/强调色仍是原组合吗？选定色调方向是否可读？主次是否更清楚？是否变成另一种天气、光照时间、人数或画风？记录 conform/partial/unclear 和具体观察，允许差异与平局。内容明显违约独立列出；不做美感排名，不以精确色值或蒙版覆盖率扣分。没有稳定收益时缩短/关闭那条规则，而不是无限加 prompt。

完成条件：三层数据的来源与未知项明确；prompt 可独立开关色调/面积；手选色板不被推荐器替换；预览/快照一致；小样本能看见方向而没有明显系统性内容变化。随后将两个独立选项加入现有首图选择器，继续默认关闭新增规则。

## 第三阶段：条件表现、画风共存与工序保留

第二阶段组合清楚后，再研究颜色如何随既有对象与生成链变化。顺序建议：

1. **少量条件表现规则**：只在描述已有玻璃、白瓷、金属、皮肤或需要的表面时考虑光泽/反射/材质的色彩规律（PDF 65、91–92）；不能为了规则添一个玻璃杯、换衣服材质或搬入书中物体。已有 7 条 scoped rules 逐条验证，别一口气全开。
2. **画风和参考角色协调**：先文字画法与主题配色，再独立研究画风图；把首图方案传递到重绘、质量/身份审计，确认审计认识已授权的颜色变化，而不是关闭门禁。参考图若泄露角色配色，应明确停止或退回文字，不能只靠深度指标当通过。
3. **工序保留与只读反馈**：比较首图和实际最终图的色板、色调及主次组织；保存每阶段继承或变化，缓存成功操作。灰度检查和知觉规则（PDF 51、99）先作为可读性提示，不自动调整构图、改固有色或硬加轮廓。不能用全图均值伪装局部效果。
4. **季节、情绪与检索**：PDF 37、53、73–74、147–148 只作用户查找/解释的标签；若用户已选固定色板，这些标签不得“更协调地”换成另一组。无合适条件就不编译。

第三阶段的成功也首先是方向和保留，而非严格区域命中。“已有图片精确改色／原生 mask”作为独立高级编辑支线保留。需要有文档、有可用接口、有明确新实验，才研究非编辑区保持；它不是第二阶段的必经路。用户禁止本地蒙版羽化、叠加和回贴的约束持续生效。

## 现在优先清理的遗留

- 文档里的“生产尚未接入”保留为历史描述，但总入口与设计应说明最新两个直接生图入口的试用接线；不要让旧报告把新状态覆盖掉。
- 模型默认值曾与预检标签不一致，今后按实际请求字段和服务端信息记录，不用固件模型替代。
- 生成成功、配色符合、内容正确、最终审计通过四件事独立记录；阶段一 sidecar 的 generated 不能叫已验证通过。
- 视觉审计仍会漏植物、误判裁切或给顶格分。保留原始请求/响应和独立纠正，不把单次模型分数当自动发布依据。
- 配置读取出现过未定位的 JSONDecodeError；新配色选择记忆采用读旧、只改自身节点、原子写。其它旧配置写入仍可能并发，尚未宣称全项目已解决。
- 第二阶段前置工作是三层对账和独立短规则编译；不是再补一轮沙洲、树冠精确改色。
