# 春日河岸钓鱼：第一阶段配色试验结果

日期：2026-10-03。实验：`spring-fishing-v1`。结论等级：单主题探索性结果；生产功能未接入。

## 1. 结论

两种配色方案都能改变这次 Gemini 直出图的颜色组织。“春绿衬粉”两张出现更集中、更沉稳的绿色基调；“柔蓝映粉”降低整体彩度，河面更显眼。**尚未证明附加方案比基线稳定更好看。** 基线本来已经很好，匿名评价的第一偏好也是基线第一张。

建议将“春绿衬粉”作为下一轮的候选，理由是此次两张均保留单人内容且配色方向可读，不是因为已经证明优于基线。“柔蓝映粉”保留为实验项：第一张生成了两个人，不能仅按颜色计为合格。

评价链路已经暴露一个重要问题：模型为其余五张的六个维度全部给了 4/4，存在明显的评分顶格、区分度不足。不能用这种评级制造方案提升百分比，也不能据此自动发布。

## 2. 本次实际执行

- 模型：`gemini-3.1-flash-image-preview`，new.aigc2d 的 Gemini 通道。
- 请求：1K、3:2、无参考图、关闭 face_quality_boost；实际六图均为 **1264×848**，不是把“1K”写成固定 1024 像素。
- 主题：粉色长发少女、春日河岸钓鱼、象牙白洋装、灰粉色带蝴蝶结的 platform heels；一人、全身、双鞋可见。
- 固定画法：细致轮廓、柔和分层绘制、可读蕾丝/裙褶、自然日光。无特定画风档案或图片，不能外推到指定画风。
- 三组各两张，顺序交错，首图直出；未运行重绘、tone、加墨或自动修订。
- 成功生成 6/6 个可读图片；内容层面明确发现 1/6 违反单人约束。所有图片保留，无补样、无删失败样本。
- 六个联网成功调用的累计客户端耗时 **88.76 秒**，单张 11.41～17.38 秒。不包含文字选择/评价调用，也不是总人工处理耗时。
- 另一次文字方案选择与一次六图匿名视觉评价，均用现有 `gpt-5.6-luna` 文字接口。未增加第七张自动选择生图。
- 本机沙箱首次禁止网络套接字，留下六个失败样本记录；自动审批放行后显式重试，成功请求均一次完成。此前失败为本地网络权限，不是服务端拒绝或内容过滤，也不能视为模型成功率样本。
- 当前项目配置允许 HTTP 内部重试一次；本次成功请求日志未显示 HTTP 重试。未查询账单，不报告金额。

协议与请求：`data/test-result/20261003/color-spring-fishing-v1/experiment.json`，初始协议 hash `6f653c562178ded3e6702e9f638c3f84e34a60466c62dede7119143e757177d3`。

## 3. 三种方案的依据

| 档案 | 配色目标 | 书中依据与本任务适配 |
|---|---|---|
| baseline | 模型自行安排 | 无附加配色条款 |
| spring-green-rose | 黄绿/深绿背景基调，已有粉发与粉鞋作为局部强调 | PDF 146 基调/强调；PDF 40 窄色相与丰富色调；PDF 79 面积主次。不给固定面积数字，不复制紫藤场景 |
| soft-river-rose | 柔蓝绿环境基调与人物暖粉形成温和对比 | PDF 146 相对颜色；PDF 53 平静情绪的浅浊色原则；PDF 147 意象轴。河蓝来自当前场景，是策划适配，不假称书中固定情绪色板 |

方案卡 HEX 是设计近似预览，不是扫描测量，未作为精确颜色数值发给模型。真正请求使用颜色名和关系条款。两种方案每组都包含四项指令，检验的是方案包，不证明某条单独理论有效。

组平均亮度/彩度：基线 0.6940/0.2636；春绿 0.6332/0.2430；柔蓝 0.7023/0.2001。

亮度是归一化 sRGB 显示空间加权值，未做线性化或校准，不等同于物理亮度或 Lab L*。近白要求三个 RGB 分量均大于 0.97，只说明图中近白区域占比，不等同于高光丢失面积。近白少不自动更好；更低彩度也不自动更好。

统计支持“方案产生颜色分布变化”，不支持“主体焦点量化提升”。没有区域蒙版或物件检测，不能把全局统计解释成脸部/服装/背景指标。柔蓝组统计仍包含双人失败图，未通过排除失败来美化均值。

模型偏好基线第一张的环境叙事和可读性；也认可春绿第二张及柔蓝第二张。**五张全部满分与文字比较存在不一致，数值不适合用于组间收益判断。** 这次评价对明显内容失败有辨识力，对高质量图之间的细微色彩差异没有足够区分度。

自动选择接口选择 spring-green-rose，主观 confidence=0.91，认为春绿环境适合衬托粉发。该数字是模型自己的主观判断，不是 91% 效果成功率；“理论选中”也不能压过实际基线获偏好的证据。

## 6. 本次主助手逐图目视复核（非人工用户打分）

查看六张原始生成图及总览，以下与外部评价分别记录：

- **baseline-1**：春景较鲜亮，河面、绿叶、远山层次和人物颜色协调；两只蝴蝶结厚底鞋可读。背景有大块粉色树冠和较多花点，但没有明显把人物淹没。还自行增加石桥，说明直接生成仍有场景自由发挥。
- **baseline-2**：大块粉色花树使粉色在人物之外也占重要位置，整体更热闹；单人钓鱼与双鞋可见。人物方向、裙摆与杆件表现跟其他图不同，说明此次不是严格逐像素或配对构图比较。
- **spring-green-rose-1**：环境更偏黄绿/深绿，小粉花替代大片粉色树冠，人物粉发、象牙裙与粉鞋集中成主体；与方案方向一致。左侧亮黄绿树丛仍有一定视觉存在感，不宜宣称背景完全不抢眼。
- **spring-green-rose-2**：深绿背景衬出人物，背景画法较柔，主体边缘和鞋饰清楚；效果更沉稳。该图明显更暗，不能把“变暗”本身当作增益；也不能确认柔化背景是颜色指令独立造成，模型随机画法仍是混杂因素。
- **soft-river-rose-1**：柔蓝河面和低彩度背景方向明显，但出现两位粉发女性，属于内容失败。不能归因为配色条款必然导致多人，也不能忽略错误只评颜色。
- **soft-river-rose-2**：单人、粉发与大块蓝绿河面对比柔和；象牙裙有较冷的阴影，鞋底和蝴蝶结清楚，适合宁静方向。未形成稳定优于基线的证据。

主要肢体与钓竿/鱼线可读，但此次没有运行项目既有逐角色人体审计、身份门禁或发布终审，不宣称所有细手指/线轴机械连接已证明正确。六图是候选实验产物，不已发布。

## 7. 对产品设计的反馈

1. 下拉菜单应提供“视觉方向”供选，而不是把某个档案写成普遍更优的“增强”。默认关闭仍合理。
2. 主体原有颜色已经可以担当强调色，不必给裙子/头发强制改色；近似色板与“保护颜色”分开显示。
3. 方案选择和效果评价是不同工序。LLM 推荐春绿，但实际评价偏好基线，产品必须允许保留基线和手动覆盖。
4. 内容有效性单列；双人错误不能被颜色好看抵消。此原则可复用到分析生图、重绘和修色阶段。
5. 色彩评价下一版增加逐对比较（基线 vs 方案，明确允许平局）与具体局部依据，保留尺度评分作为辅助。避免仅换一套权重继续平均顶格分数。
6. 下一轮若继续，优先检验春绿在不同题材/既有画风中的收益与重绘后是否保留；不能因为此次好看就立即接全 GUI。第一阶段未检验 GPT 或分析链路，文档中的接口只是接入设计。
