# 第一阶段：主题配色接入 app

状态：两个直接生成入口已实现试用接线；默认关闭。代码路径、关闭回退、快照与控件通过离线测试。没有新增在线生图验证，不能称完整生成效果已验证或精确颜色可保证。该功能的目的为呈现指定色彩组合，不是提升画质。

## 使用

“批量提示词/生图”页和“gpt-image 专用页”的画风一行新增 `配色` 与 `落点`。选择冷蓝+红、深绿+玫红或蓝紫+金，点“落点”填写正文中的环境区域与小点缀区域。可复制英文正文中的短语，以逗号分隔，例如正文已写 `sky, river water, waist ribbon sash` 时，环境填 `sky, river water`，点缀填 `waist ribbon sash`。确认这些已有区域允许换色。正文没有相应物件时修改落点或关闭，不自动添加物件。

此检查只确保文字提及，不是图像分割、语义归属或精确上色检查。自定义区域显式授权颜色变化；未列出的发色、肤色、瞳色、服装本色等保留。色板是设计近似预览，不是精确 HEX 目标。

落点窗口提供“预览当前生成条款”，只做本地编译，不联网。正文中的精确短语仅用于确认已有物件，不要求模型按像素边界或指定面积数值生成。

落点窗口可显式请求一次 LLM 推荐，发送当前文本和三个候选摘要，使用已配置文字 API。成功推荐缓存以正文、候选、模板、模型、端点为键；再次相同请求复用。点击确定应用建议，取消保留当前选择；不会自动生成图，不推断区域，也不会自动选择书中的作品、季节或人物情绪。正文改变后旧推荐不自动应用。

配色只作用于生成时的请求，不改文本输入框或源分析。批量页每个单元格提交时取当前选择，再核对该单元格正文；一个单元格已有腰带不代表另一个也有。gpt-image 请求只注入一次，aigc2d/autodl 两站点使用同一方案。

## 支持边界

- 本版只支持无图片附件的文字首图；有内容图或画风图、编辑/重绘模式时明确拒绝配色组合，不能悄悄忽略勾选。
- gpt-image 专用页启用配色时需关闭重绘及后处理开关；保留用户原开关，不自动更改默认配方。未启用配色的旧流程照旧。收费调用期间再改后处理开关也不会给本轮主题首图偷偷追加工序。
- 文字画风的已知单行 `Palette:` 字段在本次请求中去除，以主题方案承担配色；其它画法字段保留，磁盘画风配置不改。自由文本画风中的颜色要求仍可能冲突，方案带有主导权条款，但没有承诺已实现任意语义冲突识别。
- 原始 prompt 的区域存在性检查优先于衣装注入；不会把衣装规则产生的新饰品反推为原正文已有的授权点缀。
- 图片分析 Tab 的源图复现、GUI 自动审计、书籍全部 109 条来源的直接选用、第二阶段色调选项都尚未接入。三个试用预设只继承既有 Gemini 无图主题试验的有限证据；GPT、新主题和新的区域分配不继承旧成功率。

## 记录与恢复

共享逻辑 `utils/theme_color.py`、控件 `utils/theme_color_widget.py`、模板与三预设 `prompts/color-knowledge/theme-color-*`。

选择记忆位于 `conf/config.json` 的 `theme_color_ui`，按入口保存，写时先读旧文件、只更新自身节点、使用原子写；不改 API 配置、画风或衣装字段。重开详情不会发送请求，切换配色也不会收费。

提交前保存 `cache/temp/theme-color/<request_id>.json`，包含完整配色快照/hash、实际传入 worker 的 prompt 与模型/通道。批量页额外保存 instructions、post_instructions 与画幅字段；它们是提交字段快照，不冒充后端包装后的完整 HTTP body。产图旁保存同名 `.color-plan.json`，关联完整原图路径/hash。状态 generated 仅表示有产物，colour_review 保持 not_performed，不能算发布门禁通过。原输入图/模型产物均不改动，不写本地遮罩或复合图片。

成功产物保留冻结正文，不跟随控件后来变化；没有新增自动重跑收费请求。失败没有产物时保留准备/无产物记录。重新提交属于新的生成请求，本版尚无“一键按 sidecar 重跑”UI，不把界面记忆当成旧请求恢复。
