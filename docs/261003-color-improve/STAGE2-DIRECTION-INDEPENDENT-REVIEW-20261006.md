## 结论

实验已完成可复核的 10 个产图槽位与 4 组视觉评审。它支持优先继续验证“深沉”方向，支持辅助区域绑定可以改变颜色，但尚不支持声称二阶段整体已验证有效。双色并重没有建立稳定增益；明亮受基准本身偏亮和独立构图变化影响，不能把严格验收 0/2 写成“提示词完全无效”。

| 方向 | DS 记录 | Codex 看图后的判断 |
|---|---|---|
| 明亮 B | 可用成功 0/2；S1 有方向但内容不确定，S2 与 A 不明确 | S1 背景明暗有变化；S2 背景/物体比例与 A 不同，局部未呈稳定抬亮。证据弱，不等于完全不响应 |
| 深沉 C | 方向及内容通过 2/2 | S1 的海面、天空和红色强调更深；S2 的红色书封/杯子及植物阴影更深，仍有可读细节。两个单次样本的方向最清楚 |

“深沉 2/2”是方向观察及本轮候选的结果，不是统计成功率。每条件一次，全部 tone 配对评审都记录几何混杂。基准 S1-A 本身的红色也偏浅/粉，说明强调色不稳定并非已证明只由三层规则引起。

## 应补充的评审限制

1. `utils/color_direction_pack.py::_decode_directions` 当前色调方向的自动“usable”函数只读取 `content_status`。它未将 palette、protected hues、readability 和基准有效性纳入统一判定；本轮 C 的这些候选字段恰好通过，不表示该汇总逻辑以后可以作为生产验收门禁。
2. 相同 S1-A 在 tone 与 hierarchy 两组中，内容/保护色判定有不一致；`decoding.json` 对 S1-A 的部分文字概括也没有完整保留 tone 组的 protected hues 不确定性。须保留组别，不把某一组的 pass 用来擦掉另一组 uncertain。没有新增付费评审来强行消除分歧。
3. S1-B 和 S1-D 的靴子、站姿存在遮挡/重叠，原任务要求两只靴子可见。严格记录为不确定合理，但不应把该内容问题归因为“明亮/双色条款导致”；独立随机样本没有这种因果证据。
4. E 同时加了辅助绑定与层级规则。地面/桌布改为蓝灰证明授权区域响应，不能证明仅“主次面积规则”已经控制成功。辅助蓝灰也与基色方案已有蓝灰接近，看到三块物理区域不自动等于三个充分区分的色彩层级。
5. 明亮/双色的“0/2”是未达到本轮可用验收，不能写成两规则必然无效。该研究定位仍是温和提示词建议，不把观察阈值升级为严格自动上色门禁。

## 真实运行异常

DS 记录并保留了后端保存崩溃、日志跨零点及同一时段其他任务共用日志的证据。已逐字匹配实际请求，避免共同内容前缀混淆兄弟槽位。本次未因报告失败重发评审。

请求回放的凭据问题仍需优先修复：当前 `modules/others/api_backend.py::_generate_request_replay` 把 `dict(headers or {})` 直接写入 JSON，现有 header 脱敏函数没有在此调用。因此 DS 对实验内十份回放文件的事后脱敏，不等于生产回放写入已修复。当前实验目录敏感 JSON header 字段扫描未发现未脱敏值；这不覆盖其他目录、历史日志或将来的请求。不要外发整套回放目录，先修复凭据写入并核对已有受影响文件。本轮未修改该生产代码或任何密钥。
