# 配色方案接入设计与第一阶段协议

日期：2026-10-03。状态：设计 + 独立实验；生产 GUI/分析链路尚未接入。

## 1. 总体目标与边界

在分析生图与直接生图中提供同一套配色下拉选项，并支持通过现有文字分析接口请求 LLM 自动选择。配色方案独立于画风，作为任务的附加决策与可选工序；用户继续选择原有画风、模型、尺寸和参考模式。

第一阶段只验证：书中知识经任务适配，是否改变 Gemini 直出图的颜色组织，以及是否值得接入生产。不得把第一阶段结果扩大到 GPT 首图、分析复现、画风参考图重绘或后处理。此次测试是文字直出，未测试源图分析。

本文件为新的消费层设计。上游 WORK-SUMMARY 和 v2 工作流是提取过程记录，不改写历史。实测结论另见 PILOT-SPRING-FISHING-RESULTS.md。

## 2. 已核查的事实

- `data/color-knowledge/color_clauses.json`：430 条；386 stated、44 derived；其中 process 43 条、other 57 条，不直接消费为通用配色指令。stated 表示转录声称有原文依据，不等于已经证明适用于每个任务。
- `palette_library.json`：31 案例/155 色格；当前两个案例含 10 个 measured_hex，其余 29 案例尚无该字段的有效值；58 格有色表标称 RGB，97 格没有同名色表映射。标称值与扫描近似值不能混为同一来源。
- `targets/targets.json`：只有两个目标图；旧 slug 为 `color-theory-p17` / `color-case-p24`，与当前案例 slug `color-case-p022` / `color-case-p029` 不同，接入前应按来源页建立显式映射。
- `compose_color_block` 是案例资料拼接器：宽泛查询返回首个匹配，没有候选排序；混合原文与 derived 条款；未消费 measured_hex。它不是已经验证的生图方案编译器。
- `build_first_pass_request` 是 GPT 首图共用组装口；Gemini 直接生成是另一条组装链。配色要在共同任务层冻结，再由各通道适配，不能只改 GPT 函数就宣称两个通道生效。
- `resolve_style_clauses` 包含 Palette、Lighting 与保彩度的通用句。启用新的低彩度/柔和方案时必须解析这些冲突，不能盲目在末尾追加相反指令。
- `tone_calibrate` 按全图平均亮度/饱和度做有限度的确定性调整，不理解颜色区域、面积主次或焦点，不是自动配色器。
- 最终质量审计已包含实际最终候选和授权变化；仍需在集成时将配色授权明确传递到质量/身份审计及修订，而非关闭原有门禁。

事实来源：`utils/color_extract.py`、`utils/analysis_gen.py`、`utils/style_gpt.py`、`utils/post_process.py`、`utils/refine_quality.py`、`utils/identity_audit.py`；以上是 2026-10-03 工作区现状。

## 3. 知识的可靠使用方式

总纲采用 PDF 146 五步法：意图、色调、选择颜色、构建基调、安排强调。书里抽取五个主色用于分析，不要求每张生成图只能有五色。

运行档案保留三层：原文来源/事实、策划者的适配、实际英文生成条款。原文引用不直接塞进请求。案例数值比例只在适用时使用，不把室内 60/30/10 或某个作品的比值改为普适门槛。

色值来源枚举：`scan_measured`、`table_nominal`、`designer_approximation`、`unknown`。实验方案卡的 HEX 属于 designer_approximation，不冒充书中测量；此次请求使用相对关系和颜色名，不要求模型精确执行 HEX。

案例原作图片不作为生成附件。借用关系与方法，禁止迁移案例角色、动作、物件、服装或画师姓名。无合适方案时选择关闭/基线，不硬凑。

## 4. 产品交互（待实施）

### 4.1 共享选项

紧凑一行：`配色方案 [关闭/保留原配色改善层次/已验证档案…] [LLM 推荐] [方案详情]`。

“LLM 推荐”是显式动作，使用已经配置的文字接口；不在每次切换控件时收费。成功后显示所选档案与理由，用户可手动覆盖；生成时冻结选择。默认关闭，实验档案先标“实验”。

分析生图输入是事实描述、源图颜色约束及当前画风；直接生图输入是用户描述、画风和显式颜色。自动选择只读候选摘要，不发送整本书。

### 4.2 修改范围

默认保护发色/瞳色/肤色倾向/服装标志色/角色身份、动作、构图、对象。背景配色与环境光也要服从原任务的忠实度：源图复现模式默认仅改善层次；重新配色模式允许用户明确选择背景、服装、饰品等区域。既有画风已授权设计变化的条款继续有效。

“关闭”“保留原配色改善层次”“按档案重新组织允许区域”是作用模式；“春绿衬粉”等是档案，避免把作用范围藏在档案名称里。

### 4.3 用户产物

- 生成前：方案卡（意图、近似色板、基调/辅助/强调、落点、保护颜色、预期影响、冲突和来源）。
- 生成后：对比图、逐项配色执行反馈、内容缺陷与不确定性独立列出。
- 展开详情：实际短条款、来源页、适配理由、模型与请求 hash、各阶段继承/变化记录。
- 不新增分析 Tab 常驻行，不挤占队列/日志；复用滚动选项区的紧凑控件与独立详情窗口。

## 5. 任务契约与工序（待实施）

建议 `color_plan` 的必要字段：schema_version、profile_id/version、selection_mode（manual/llm/off）、reason、intent、tone_strategy、roles（color/region/role/relative_area）、protected_colors、allowed_changes、source_refs、adaptations、compiled_clauses、conflicts、plan_hash。

色板 preview 与执行条款分开存储；无可靠数值时用关系描述，不编造面积或色值。LLM 的 confidence 标为主观置信度，不能显示成实测成功率。

| 工序 | 责任 | 首期状态 |
|---|---|---|
| 选择/规划 | 闭集方案选择、兼容检查，冻结快照 | CLI 独立试验 |
| 通道编译 | 内容/身份/画法/配色分离，协调 Palette/Lighting，限制长度 | 独立 Gemini 请求 |
| 首图 | 执行任务配色，记录实际请求 | 在线试验 |
| 画风重绘 | 保留已批准配色，仅迁移画法 | 尚未接入 |
| 质量/身份修订 | 相对于内容约束及配色授权评价，不撤销已授权颜色 | 尚未接入 |
| 可选 tone | 独立目标与强度，不随档案自动切换目标图 | 本次关闭 |
| 配色评价 | 看实际阶段图与方案，局部反馈 | 一次匿名模型评价 + 人工复核 |
| 局部配色修订 | 有明确问题才提出；收费、范围与最大轮次可控 | 尚未实现 |
| 最终门禁 | 内容/人体/质量门禁保持，配色先建议性 | 尚未接入 |

普通续跑保留旧方案；换方案建立新尝试，原图/原尝试保留。方案 hash 进入请求和相关下游缓存依赖，选择、生成、评价成功均复用；拒绝/空响应/非法档案不冒充成功，停止依赖步骤。选择失败保留手动选择入口，不静默替换既定方案。

未来首次插入人体等原有门禁不允许被配色分数覆盖，不能以“配色好看”把失败任务标绿。新方案不能依赖关闭身份门禁获得效果。

## 6. 色彩评价模式

### 6.1 分开回答三个问题

1. 方案适配：与任务身份、画风、构图及授权是否兼容？
2. 执行符合度：生成图是否实现基调/强调/落点/光照关系？
3. 视觉收益：人物更清晰、层次更好、情绪更合适吗？

第一阶段匿名评价主要看第 3 项与内容保护；不把“更接近参考案例”直接当作视觉收益。后续方案符合度由另一轮对照评价处理，避免先告诉评价模型预期赢家。

### 6.2 输出结构

六个独立 0..4 等级：颜色主次、主体焦点、明暗彩度层次、主题氛围、内容保持、画法质量。等级是有锚点的主观模型评级，不是连续测量。每图带具体观察、缺陷、不确定性。内容错误单列，色彩均分不掩盖鞋型/钓竿/肢体问题。

本地统计输出：尺寸、显示空间亮度均值与 P10/P50/P90、HSV 平均饱和度、近白像素比例。它们用于解释变化，不用于自动排名。没有语义蒙版，不宣称测得脸部焦点、主辅色面积或身份色误差。HSV 直方图以后可作分布描述，不作好看与否的主证据。

生产初期配色评价仅给建议，不设通用美学发布门禁。方案选择、生成、评价收费独立；不能默认每图再多跑多轮修色。

## 7. 第一阶段预先固定的实验协议

主题：粉色长发少女，春天河边钓鱼，洋装，带蝴蝶结的 platform heels。为使颜色保护可比较，本次固定象牙白洋装和灰粉鞋；这是试验补充，不推广为产品默认。英文用 young woman 表达，保持用户指定的少女插画形象。

固定主体、画法、构图、对象、模型、尺寸；不挂画风/案例图。三组每组两张，共六张，重复间交错：baseline → 春绿衬粉 → 柔蓝映粉。Gemini Flash 1K，3:2，以 spec 文件配置为准；调用 new.aigc2d；不声称具体价格，实际账单另核。

处理变量：两种附加配色条款。两种处理都在一次关系规划中包含数项颜色指令，所以只检验整个方案包，不归因于某一单句规则。随机生成无配对 seed，每组两张只是探索性样本，不作显著性或泛化声明。

不加重绘/tone/加墨。LLM 自动选择另请求一次，只选择这三个闭集档案，不自动追加第七张生图。评价随机重排样本并使用 V01..V06 中性编号，评价接口看不到处理标签；评价文件保留映射用于复核。模型自身可能偏好某种风格，仍需人工查看。

验收：六次均有可读非空产物；请求/协议/耗时/成功失败已落盘；对比图与本地统计齐备；自动选择返回合法档案和理由；模型评价覆盖每图且评分有效；人工检查至少主体/钓竿/双鞋与颜色焦点；结论列出 mixed/uncertain，不追补图片挑赢家。

结果分级：有变化 ≠ 有收益；一次主题下两张同向也仅是该任务的初步支持。至少跨题材/画风复验后才可作为默认推荐。下一阶段优先检验有效方案的重绘保留，再测分析生图，不急于实现所有 GUI。
