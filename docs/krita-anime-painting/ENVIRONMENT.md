# 先探索环境，再选择画法与工具

这份包可在未安装绘画软件的机器上阅读。Krita 和 MCP 是原作者的执行环境，不是知识学习的前提，也不是接收方已具备的条件。

## 第一轮只读确认

先读接收方项目说明和适用的 AGENTS.md，确认工作目录、可写位置与用户授权。再检查以下事实；没有依据写 unknown，不猜“已启动”或“已连接”。

| 项目 | 应确认的内容 |
|---|---|
| 系统和运行时 | Windows/macOS/Linux；Python 是否可用、实际版本和命令；不照抄盘符 |
| 绘画软件 | 可用软件、版本、真实安装位置；是否已打开文档及有未保存工作 |
| 自动化入口 | 会话实际提供的工具；插件是否启用；MCP 客户端与软件桥接是不同环节 |
| 权限和能力 | 允许读写的位置、是否可连接本机接口；能否建文档、画图层、导出并读图 |
| 资源 | 实际笔刷准确名称、滤镜参数、字体；资源许可、数位笔压感/倾斜能力 |
| 输入 | 参考图是否真的收到、可读；历史场景依赖是否存在 |

有 Python 时可选择运行只读辅助探查：

```text
python docs/krita-anime-painting/tools/explore_environment.py
python docs/krita-anime-painting/tools/explore_environment.py --krita-path <候选路径> --bridge-file <实际配置路径>
```

脚本只检查平台、PATH、少数标准位置和候选文件存在性；不启动应用、不安装插件、不扫描端口、不连接服务、不读取或输出令牌。未找到不证明没安装，需结合用户路径或系统应用列表确认。

## 按实际结果分流

| 环境 | 下一步 |
|---|---|
| 无绘画软件或无 Krita | 先读手册、看示例、写要素和评审；实际画图前确认可用软件或安装意愿，不静默安装或声称已经绘制。 |
| 有其他绘画软件 | 迁移形体、光影、工序原则；按该软件实际接口实现，不把 Krita 命令当通用协议。 |
| 有 Krita、无自动化入口 | 可人工绘制；若需要自动化，先查对应版本官方插件/脚本支持，安装和启动按实际授权处理。 |
| 有 MCP、未知是否连接 Krita | 检查实际暴露工具；装了 MCP 不代表支持 Krita 或 `run_python`。 |
| 有 Krita 与兼容接口 | 先读状态/能力，再用新文档小样测试绘制、保存和导出，确认后运行完整场景。 |

## 原作者机器事实，仅作适配示例

2026-10-17 本机为 Windows、Krita 5.3.3。程序在 `C:\Program Files\Krita (x64)\bin\krita.exe`，插件连接信息在 `%APPDATA%\krita\krita_mcp_bridge.json`，当时使用回环端口 9797。路径、端口、协议、版本和 PyQt5 支持均不能外推到朋友机器。

`tools/krita_studio.py` 为这个特定桥接编写：读取上述 Windows 配置中的 port/token，向回环 `/rpc` 发送操作。它不是标准 MCP 客户端，也不是任意 Krita 插件都支持的接口；知识包没有提供插件安装程序。其他系统或桥接应先适配，不能直接运行后把报错解释成“没装 Krita”。

确认接口兼容后才使用 `status`、`inventory`。`inventory` 通过插件 `run_python` 读取能力，不属于无需桥接的离线探查。令牌留在接收方本地，协作报告只写能力状态。

## 探索完成记录

复制 [环境记录模板](templates/environment-report.template.json)，填写事实、unknown、依据与下一步。输出使用接收方自己的目录；不要运行所有历史脚本来探环境，它们有顶层写文件行为和活动文档依赖。
