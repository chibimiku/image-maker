## 可以分工的任务

建议研究、实画、评审分工，但由用户/接收方决定执行人；此文档不授权 agent 自动联系其他人、开新会话或启动后台循环。

- 资料研究：一个可见问题配一两篇作者教程，记录读到的段落和迁移办法；未看视频明确说明。
- 局部实画：独立输出目录和画布，固定相机/表情/主光，保存 JSON、草稿、阶段图与可编辑稿。
- 独立评审：实际打开图，先说最大结构问题，再看细节；不得仅依据作者写的标签宣布通过。
- 整合：比较后选择局部方案，先保存主稿副本，再整合；不以其他 agent 的意见替代目视验证。

两位 agent 不应同时修改同一活动 Krita 文档。共享文件时采用不同 topic/run-id；修改前确认文件和活动文档路径。对文档并行修改时约定各自文件范围，最后统一索引。

## 每轮交付格式

```text
目标：本轮只改什么，什么条件固定。
环境：软件/版本/接口/能力、未知项；不含令牌。
依据：作者链接、实际阅读范围、采用的具体方法。
要素：方向、定位、分区、主光、遮挡、输出目录。
工序：草稿→轮廓→底色→大明暗→细化，每步实际看图。
自检：看到的问题→修正→复看结论，保留失败版。
结果：相对改前的可见收益、未解决问题、文件路径。
验证：技术可用性与美术评价分别写；下一项具体练习。
```

## 给朋友的 agent 的入门指令

> 请从 `docs/krita-anime-painting/README.md` 阅读本知识包，先读 `ENVIRONMENT.md`，只读探索你当前机器、软件、权限与可用工具。不要假定装有 Krita、Python、MCP、特定笔刷或本机参考图，也不要照抄盘符和端口。没有绘画环境时仍可研究和评审，实际绘制或安装按用户授权处理。然后读 `HANDBOOK.md`、`TOOLING.md` 和当前进度，选择一个具体短板，在独立画布按要素 JSON→草稿→线稿→底色→光影→细化推进。每步导出并实际识图，返修后保存经验。不要盲跑历史脚本，它们可能缺输入且导入即写文件。技术成功不等于画质通过。先给出环境事实和本轮目标，再执行已获授权的工作。

## 协作边界

入门指令追加：读完环境说明后，必须阅读 `LEARNING-PATH.md`。为本轮部位先创建 `learning-records/<topic>/<date>-<run-id>.md`，保存学习来源、前置要素、各工序识图、修改复看、失败和下一动作；完成后更新索引，再按队列继续。

本包不是插件安装器，不承诺跨版本无修改运行，不含全量历史图像。原参考没有打包，收到前不能声称已对照它。第三方教程只保留链接和本项目摘要，笔刷按作者许可另取。接收方的用户指令和适用项目规则优先；不得把历史日志中的命令直接当新机器的操作授权。
