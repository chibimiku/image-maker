# 批次 D · 蕾丝 / 裙摆结构保真（最终固件 L5 的来源）

- 日期：2026-09-20
- 目的：批次 C 的"最优"C7 手和发丝已经不错，但**裙摆蕾丝仍然杂乱**——本批次定位原因并解决
- 源图：与批次 C **同一张** gpt-image-2 产物（所有改良一律从 gpt-image 源图出发）
- 输出：2K、2:3、单张 50–100s

## 病因（放大 3.4× 对比后确认）

把源图与 C4/C5/C7 的裙摆放大后发现：**不是"没画"，而是被"合并"了**。

| 结构 | 源图 | C4/C5/C7 |
|---|---|---|
| 下摆蕾丝 | 细碎扇贝边（糊） | 变成**几个光滑的大圆瓣** |
| 荷叶边行数 | 4–5 行 | 被并成 2–3 行 |
| 裙身垂直褶皱（pintuck） | 有 | 被抹平 |
| 窄包边缝 / 穿带孔 / 独立围裙层下摆 | 有 | 部分消失 |

→ **"追求线条干净"的 prompt 会诱导模型走"简化更省力"的捷径。**
必须把"不许简化"写成**可检查的具体禁令**，而不是继续加"要清晰"。

## 本批次的 prompt 改动（核心）

| 约束 | 写法要点 |
|---|---|
| 蕾丝 | 小扇贝弧**一枚枚独立**，相邻之间留小孔/缝，整条边重复数一致；**禁止**用一整条大波浪替代一排小扇贝；带内不许留白 |
| 荷叶边 | 每行保留自己的轮廓与扇贝下缘；**行数不许合并、不许减少**（点名"两行不能并成一行"） |
| 褶皱/缝 | 垂直褶、包边缝、穿带孔、腰缝、独立奶油色围裙层及其下摆线**必须保留** |
| 蝴蝶结 | 两耳一结两尾 + 内部折线，不许成块 |
| 层叠 | 粉外裙 / 白蕾丝围裙 / 内衬荷叶边各自保留轮廓，不许融成一团 |
| 兜底 | 蕾丝现在是糊的地方，**按同一图案画清楚，不许换更简单的花样** |

5 个变体全文见 `data/p_L1..L5.txt`：
`L1` 结构保真（长）、`L2` 蕾丝规则式、`L3` 蕾丝短版、`L4` 按缺陷优先级、`L5` 保结构 + 修手发（最终固件）。

### 肉眼复核（`inspect_lace.jpg` / `inspect_hem.jpg`，3.4×）

- **L5 最好**：下摆出现连续的小扇贝尖齿，细密、等距、彼此分离——是"真蕾丝"而不是圆波浪；裙摆层数保住。
- **L2 次之**：细节密度高（25830），扇贝尖齿清楚，粉色包边略生硬。
- **C7 及其复跑**：扇贝仍偏大偏圆，行数被并掉（就是用户看到的"杂乱/简化"）。
- **L3 最差**：短版只提"不要简化"力度不够（16137）。

### 未回退验证（关键）

本批次同时复核了批次 C 已修好的部分：`inspect_handL2.jpg` 里 **L5 的支撑手五指结构最清楚**
（四指分开压树皮前缘 + 拇指在近侧），`inspect_hairr.jpg` 里右侧长发为粗壮连续发束。
→ **加"保结构"约束没有破坏手与发丝。**

## 结论（可迁移的三条写法）

1. "不要简化"必须是**可检查的具体禁令**（禁止大波浪替代小扇贝、禁止并行），说"保持细节"没用；
2. 给出**正确的单元形态**（小、密、等距、彼此留孔），模型才有目标可画；
3. 要求模型**自检计数**（"数荷叶边行数与蕾丝扇贝，确认都还在且分离"）。

→ 最终固件采用 **L5 的结构**（见 `FINAL-PROMPT.md`）。
