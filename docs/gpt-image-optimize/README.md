# gpt-image 产物优化（Gemini 重绘提线）· 理论与实验全记录

> 目的：让 gpt-image（`gpt-image-2` / `2.5`）在**动画 / anime 风格**出图上"线条连续、细节清晰、蕾丝不糊、手指不崩"。
> 结论先给：**光靠改 gpt-image 的提示词只能治一半，最后一步必须由 Gemini 3 Pro Image
> 对 gpt-image 的产物做一次「重绘提线」**；本目录记录这条路线的全部依据、可复现实验与固件。
>
> 落到程序上的入口：
> - GUI：`app.py` → 生成 Tab → **gpt-image-2 生图/编辑** → 模式「重绘(Gemini优化产物)」，
>   或生图模式下勾选「生图后立即重绘（以重绘结果作为产物）」。
> - CLI：`python tools/gpt_image2_gen.py --repaint --image <产物.png>`
> - 固件：`prompts/gpt-image-optimize/repaint-system.md`（本目录的 `FINAL-PROMPT.md` 是同内容快照）
> - 配置：`prompts/gpt-image-optimize/config.json`（模型 / 分辨率 / 宽高比 / 重复次数 / 目录）
> - 运行时：`utils/gpt_image_optimize.py`、`modules/others/api_backend.py::generate_image_repaint`

## 1. 问题定义

gpt-image 在 anime 风格上的两个稳定短板（用户实测反馈 + 本目录实验复现）：

1. **线条连续性差**：轮廓线细、断续、在渐变区消失；放大后头发内部是"涂抹"而不是发丝。
2. **细节模糊 / 乱**：蕾丝、荷叶边、褶皱这类**高频重复结构**要么糊成一团，要么被"合并"成几个大圆瓣。

本目录把这两个问题拆成三个可测量的量：**锐度**（line sharpness）、**连续性**（line continuity）、
**结构保真**（structure fidelity）。指标定义见 `metrics.md`。

## 2. 核心理论：生成模型有一个「细节预算」

这是整条路线的理论出发点，也是解释所有实验现象的关键。

### 2.1 细节预算模型

把一次生成看成按固定预算分配"可辨认的边"：

```
总细节预算 ≈ 强边像素数（梯度 > 20% 峰值的像素）
每帧预算大致恒定 →  元素越多 × 每个元素越细 = 单元素分到的边越少
```

实测证据（同一 1024×1536 画布，`data/experiments-A` 表）：

| 样本 | 强边像素数 | 平坦区(<2%) | 渐变区(2–10%) | 量化色数 | 观感 |
|---|---|---|---|---|---|
| 极简 prompt 产物（自生成，无角色/场景描述） | 91,575 | 71.3% | 16.4% | 498 | **线条最干净** |
| 高细节满构图（湖景 + 树 + 多层蕾丝） | 114,484 | 42.3% | 37.8% | 1095 | 发虚 |
| 同上，更细的 prompt | 147,850 | 36.2% | 38.8% | 996 | 更糊 |
| 同上，模型换成 2.5-flare | 221,590 | 32.2% | 36.5% | 1170 | 细节多但边缘更碎 |

推论：
- **"渐变区"是糊感的来源**：那里没有归属明确的边界，放大后就是涂抹。
- 元素越多，模型越倾向用"渐变/涂抹"去凑细节，线条预算被摊薄。
- 因此**降复杂度**（缩景 / 限预算）与**换更强的重绘模型**是两条有效路径，
  而"再多加一句要清晰"是无效路径（见批次 B）。

### 2.2 为什么"重绘"能突破这个预算

Gemini 3 Pro Image 的输入包含**已经画好的图**——它不是在空白上分配预算，
而是在**已知结构**上重画线条。于是它可以：

- 用"平涂 + 硬边"重述原图（把渐变区改写成明确的色块边界）；
- 把源图里"糊掉了但确实存在"的结构（蕾丝单元、发束）**按源图的图案重画清楚**；
- 修掉源图的解剖错误（手指数、关节），因为 prompt 明确要求"不要复制源图的手"。

代价（必须知道）：**重绘是重画，不是无损放大**。构图会小幅漂移（衣摆位置、腿部姿态、
背景树叶分布），五官会有轻微重绘感。所以重绘的定位是"最后一次提线"，不是"替代生图"。

### 2.3 三条被实验证伪/证实的设计假设

| 假设 | 实验 | 结论 |
|---|---|---|
| 只要 prompt 里多写"clean line art / crisp detail"就能变清晰 | 批次 B（B0/B3/B4） | **不成立**。只加风格名词几乎无收益（B3 与基线同值）；单次抽卡波动可达 ±60%，必须复跑 |
| 只要要求"不要简化"，蕾丝就不会被合并 | 批次 D（首次 A1/C4/C5/C7 之后） | **部分成立**。必须把"不许简化"写成**可检查的具体禁令**（禁止大波浪替代小扇贝 / 禁止并行 / 给出单元形态），否则模型会走"简化更省力"的路 |
| 修错指令会让画风变差 | 批次 C/D | **不成立**。明确"源图的手是坏的，请重建，不要复制"之后，手/发丝变好，画风指标同时提升 |

## 3. 方法学（怎么测才不会骗自己）

1. **同源对比**：所有重绘都从**同一张 gpt-image 产物**出发（`data/20260919/anime_lolita_cmp_v3/gpt-image-2_output_193138_0_d09c70.png`，1024×1536）。
2. **固定参数**：`model` / `size` / `quality` / `output_format` / `n` / 是否带参考图 全部固定，只改被考察的那一项。
3. **统一缩放后再测**：重绘产物是 1696×2528（2K 2:3），必须缩到**同宽 1024** 再算指标，否则锐度指标会被分辨率白送。
4. **关键版本必须复跑**：同一 prompt 两次结果的 lap_var 实测可差 40–60%（B0 845/725、B4 1509/926、C4 2336/2059）。
   **单跑一次就下结论 = 抽卡**。
5. **指标要配对看**：锐度类（lap_var / tenengrad / edge_soft）与保真类（lace_teng / frill_cycles / colors）方向可能相反，
   必须和肉眼放大图一起判。
6. **指标有偏**：`frag`（细线碎片率）在**密集蕾丝图**上会误判"细节多 = 线碎"，详见 `metrics.md` 第 3 节。

## 4. 跨批次总结论

### 4.1 批次 A：gpt-image-2 vs 2.5（`experiments-A-...md`）

| 模型 | lap_var↑ | tenengrad↑ | 边缘密度 | 碎片率↓ | 梯度>30% 占比↑ |
|---|---|---|---|---|---|
| gpt-image-2 | 1181 | 7420 | 0.1148 | 0.0202 | 4.07% |
| **2.5-flare** | **1506** | **9020** | **0.1354** | 0.0236 | **6.63%** |
| 2.5-sunburst | 953 | 7522 | 0.1244 | **0.0153** | 5.05% |
| 2.5-flare-c（按次计费） | 718 | 5534 | 0.0844 | 0.0148 | 3.17% |

- 2.5 确实改善了线条与细节；**flare 最锐**，**sunburst 最连贯**。
- `-c` 计费通道同参数下明显更软，不用于线条对比。
- **safety 差异**：同一份详细 Lolita prompt，gpt-image-2 稳定通过，2.5-flare/flare-c 连续被拒 6 次；
  压成一行、缩短、去掉年龄与袜类描述后一次通过。→ 2.5 的 moderation 明显更严。

### 4.2 批次 B：只改前置画风 prompt（`experiments-B-...md`）

- 只加风格名词：**要么无收益（B3 ≈ 基线），要么拆东墙补西墙**（B1/B2 的 soft↓ 但 frag↑）。
- **唯一复现成功的写法**：前置钉画风 + 后置钉**可检查要求**（B5：soft 25.7%/25.2% 两次都最低）。
- 前置里写"职业动画师用细笔绘制"这类语境词 ≈ 无效。
- 结论：**改 prompt 能小幅帮上忙，但换不来根本改善** → 需要重绘。

### 4.3 批次 C：Gemini 重绘修手/发丝（`experiments-C-...md`）

源图 → Gemini 3 Pro Image（2K，2:3，30–90s/张）9 个变体，关键行：

| 变体 | 指令结构 | lap_var↑ | soft↓ | edge/soft↑ | 手 | 发丝 |
|---|---|---|---|---|---|---|
| A1 | 只要求"赛璐璐风格重绘" | 2628 | 20.1% | 0.699 | **复制了源图的坏手** | 一般 |
| C4 | 负面清单优先 | 2336/2059 | **18.2/27.6%** | 0.734/0.431 | 好 | 好（复跑稳定） |
| **C7** | C4 结构 + 分优先级 | 2268 | 26.3% | 0.503 | **最好** | **最好** |
| C5 | 画风段 + 修复段合并 | 2993 | 22.2% | 0.668 | 很好 | 很好 |
| C1 | 一次要求太多（修手+修发+保画风+全画面） | 1684 | 35.5% | 0.301 | 一般 | 一般 |

**最重要的发现**：A1 这类"只要求重绘风格"的 prompt 会**忠实复制源图的错误**（手是坏的 → 重绘后还是坏的）。
必须显式写 `the source hands are malformed - reconstruct, do not copy` 才会动刀。这一句是批次 C 的核心增量。

### 4.4 批次 D：蕾丝/裙摆保真（`experiments-D-...md`）

C4/C5/C7 的蕾丝仍然"被化简"——放大可见**小扇贝被合并成大圆瓣、荷叶边行数被并掉、垂直褶被抹平**。
批次 D 把"不许简化"写成硬约束后：

| 变体 | 裙摆细节能量 lace_teng↑ | 硬边占比↑ | 褶计数 frill_cycles↑ | 裙身能量↑ |
|---|---|---|---|---|
| 源图 | 12139 | 8.40% | 0.585 | 13195 |
| C7（批次 D 前的"最优"） | 18918 | 14.59% | 0.444 | 26995 |
| L2 蕾丝规则式 | 25830 | 17.64% | 0.461 | 32930 |
| **L5 保结构 + 修手发** | **29169** | **19.38%** | 0.441 | **35092** |
| C7 复跑 | 25980 | 17.04% | 0.519 | 35951 |

- **L5 是最终固件**：蕾丝细节第一，手/发丝同时保持最好，且与上批已修好的部分不冲突（放大复核过）。
- 可迁移的三条写法规律：
  1. "不要简化"必须是**可检查的具体禁令**，不是"保持细节"；
  2. 给出**正确的单元形态**（小、密、等距、彼此留孔），模型才有目标；
  3. 要求模型**自检计数**（"数荷叶边行数与蕾丝扇贝，确认都还在且分离"）。

### 4.5 总路线（最终建议）

```
gpt-image 出图（想更锐选 2.5-flare）
   ↓  同一张产物，原样送去
Gemini 3 Pro Image 重绘提线（本目录固件，2K，2:3，每张跑 2~3 次挑最好的）
   ↓
最终产物 = 重绘结果（构图不变、线条连续、蕾丝结构保住、手修好）
```

- 重绘是**抽卡**：同一 prompt 建议 `repeat=2~3`，挑手与发丝最好的那张（GUI 有「每张重绘次数」）。
- 想让 gpt-image 一次到位：可把批次 B 的 B5 写法合进生图 prompt，但**不要指望它替代重绘**。

## 5. 固件（prompt）说明

`FINAL-PROMPT.md` 是快照，运行时读的是 `prompts/gpt-image-optimize/` 下的两个文件：

| 文件 | 作用 | 不可删的理由 |
|---|---|---|
| `repaint-system.md` | 主 prompt：先钉"不是新图"，再钉"不许简化"，再按优先级修手/发丝/其他，最后给画风与自检 | 缺它重绘会退化成"A1 式重绘"，把源图的手一起复制过去 |
| `repaint-detail-suffix.md` | 细节强化后缀（独立段落追加） | 实测把要求写成第二段比挤在结尾逗号里更稳 |

改 prompt 后请：
1. 至少复跑同一张源图 **2 次**；
2. 用 `tools/ab_metrics.py` + `tools/lace_metrics.py` 对比 `lap_var / soft / edge_soft / lace_teng / frill_cycles`；
3. 用 `tools/crop_inspect.py` 出 2–3× 局部放大图肉眼确认（手 / 右侧发丝 / 裙摆蕾丝），再决定是否替换固件。

## 6. 落地用法

### GUI

1. `python app.py` → 生成 Tab → **gpt-image-2 生图/编辑**。
2. 两种方式：
   - **生图后立即重绘**：模式=生图，勾选「生图后立即重绘（以重绘结果作为产物）」→「开始生成」。
     结果列表里只出现**重绘产物**，原始产物路径写在日志里（可对比）。
   - **对已有产物重绘**：模式=**重绘(Gemini优化产物)**，把产物拖进「参考图」区（或「添加图片」）→「开始生成」。
     另有快捷按钮：「重绘结果列表的图」（不用先搬图）、「把结果加入参考图」（迭代重绘）。
3. 重绘模型 / 分辨率 / **输出宽高比** / 每张次数在界面上可直接改，会写回 `prompts/gpt-image-optimize/config.json`。

### 宽高比：默认 auto（跟随源图），不要写死

**这是必须遵守的一条**：写死一个比例（例如 `2:3`）会让非该比例的源图被拉伸或裁切。官方明确：

> By default, the model matches the output image size to that of your input image,
> or otherwise generates 1:1 squares.
> —— [Gemini API · Image generation](https://ai.google.dev/gemini-api/docs/image-generation)

因此本功能的默认值是 `"aspect_ratio": "auto"`，语义是**不下发 `aspectRatio` 字段**，
由模型按输入图比例输出（`modules/others/api_backend.py` 里对 `auto/空/跟随源图/keep/same` 等别名统一处理）。
只有确实要强制输出比例时才在界面选具体值（或 CLI 传 `--repaint-aspect 16:9`）。

界面提示栏会读源图像素并显示实际比例（`utils/gpt_image_optimize.image_aspect_ratio_label`），
选了非 auto 时会标成「强制，可能与源图不一致」，避免踩坑。

已支持的比例清单（官方）：`1:1 / 3:2 / 2:3 / 3:4 / 4:3 / 4:5 / 5:4 / 9:16 / 16:9 / 21:9`。

### CLI

```powershell
# 看最终固件（不调接口）
python tools/gpt_image2_gen.py --repaint-show-prompt

# 对一批产物重绘（每张 2 次，抽卡）—— 输出比例默认 auto，跟随每张源图
python tools/gpt_image2_gen.py --repaint --image data\...\a.png --image data\...\b.png --repaint-repeat 2

# 确实需要强制比例时才加（不推荐，可能拉伸）
python tools/gpt_image2_gen.py --repaint --image a.png --repaint-aspect 16:9

# 临时换提示词文件
python tools/gpt_image2_gen.py --repaint --image a.png --repaint-prompt-file prompts/gpt-image-optimize/repaint-system.md
```
