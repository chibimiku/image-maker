# GPT 单图超时与界面预算同步 — 2026-10-14

用户反馈 GPT Image 2 单图接口 109 秒成功，但本地界面已显示超时处理。

定位：分析页的新默认直出模式将通用超时值直接用作 GUI 取消截止时间，而 GPT HTTP 后端默认等待 600 秒。GUI 到点会请求中断，之后返回的成功响应可能被取消逻辑丢弃。并发任务还会因为只在第一个任务启动计时而继承更早的截止时间。没有找到该次请求对应的唯一记录，因此这是代码层面确认的缺陷，不声称已对用户该次 109 秒响应逐条复现。

修复：

- `gpt_image_workflow.timeout_seconds` 默认及此机实际配置为 600。设置 → GPT 出图 API → GPT配置新增「GPT 请求超时」，范围 30–3600 秒。
- GPT 单次 HTTP 超时读取独立值，包括共享 Gemini URL/key 的模式；Gemini 自身超时不变。
- 界面预算依据该 HTTP 超时计算，包括允许的网络重试、上游错误重发、generate 带图时的 edits 回退，以及 30 秒本地收尾余量。并非把总预算固定为单次 600 秒。
- 无重试 edit 请求为 630 秒；现有默认带参考图 generate 路径的最坏总预算会更长。并未新增重试次数。
- 工序开启时，原工序预算保留，并补足 GPT 首图的独立预算。
- 每次加入新生图任务都更新预算，截止时间只延长、不缩短。手动取消行为保留。
- CLI 的显式 `--timeout` 在临时配置副本中同步独立 GPT 超时字段，不回写公共配置。

## 超时分类整理 — 2026-10-14

将常用请求超时按单次网络调用拆成三项：

- **Gemini 单次生图**：图片生成 API 节点的 `timeout`，设置页显示为「Gemini 单次生图超时」。
- **GPT-image-2 单次生图**：`gpt_image_workflow.timeout_seconds`，默认 600 秒；共享 Gemini URL/key 时也不共享超时值。
- **文本分析单次请求**：设置页「文本分析 API」中的独立值，保存到 `config-image.json` 顶层 `text_analysis_timeout_seconds`，新配置默认 120 秒；旧配置若无此字段，首次沿用原图片 API timeout，避免升级时改变原有分析时限。单图分析、批量分析和多图画风分析均读取该值；每次文本 HTTP 请求各自计时，不把多步流程误显示成单一请求截止点。

Gemini/GPT 生图任务的 GUI 倒计时是工作流预算，按请求次数、已有重试/回退和后续工序另算，不作为单次 HTTP 超时值。首图审计、refine 审计等有意独立的审计窗口仍按各自配置/预算执行。
