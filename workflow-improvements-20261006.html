二、任务 2：每轮出图后的对比报告（已实现）

新增 utils/generation_report.py（报告引擎）+ tools/make_generation_report.py（CLI）。

报告包含什么

节内容解决的原问题
一、候选 × 参考参考图缩略图 + 八组指标 + 「最像/最不像哪张参考」以前只有整轮结束才出一次报告（automatic-comparison.html）
二、泛化对照每个候选 × 每一张参考图的中位/最好/最差 + 配对数画风提取常用 10+ 张来源图，只看单张参考会过拟合
三、参考图墙本次用到的全部参考图缩略图报告里看不到"到底比了哪些图"
四、推荐 prompt 组合按 gram 中位排序 + 推荐使用哪一版以前选型靠人工翻目录
六、大模型打分视觉模型 0-100 分 + 分项 + 依据（见任务 3）本地指标没有"判断"，只有数值

用法

# 某一个实验轮次（每个画风各出一份）
python tools/make_generation_report.py --label round21

# 只出某个画风
python tools/make_generation_report.py --label round19 --style komori-hikki-style

# 显式指定（画风名会自动查参考图）
python tools/make_generation_report.py --style cccccanh --images a.jpg b.jpg

# 多参考泛化对照（画风提取的 10+ 张来源）
python tools/make_generation_report.py --references r1.jpg r2.jpg r3.jpg --images c1.jpg c2.jpg --out report.html

实测已生成：data/test-result/style-lab/reports/report-round19-*.html（6 个画风）、 report-round21-komori-hikki-style.html。指标复用共享入口 utils.style_similarity.compare_images， 没有复制任何公式；设备默认 auto-cpu，批处理可设 IMAGE_MAKER_REPORT_DEVICE=cuda。

还没接进「每轮自动触发」：多图画风提取的轮内循环在 modules/image_analysis/style_analyzer.py:1205 附近 （每轮 _save_state 之后），现在报告仍是"跑完一轮后用 CLI 生成"。 接进 GUI 需要给 write_comparison_report 加输出名参数（它固定写 automatic-comparison.html）， 并考虑轮内自动跑指标会占用 CPU/GPU —— 建议作为下一步单独改，避免一次动太多测试面。

三、任务 3：把对比图交给大模型打分（已实现）

新增 utils/llm_style_score.py + tools/llm_style_score.py， 复用现有文字/视觉分析接口（utils.analysis_gpt_prompt.call_text_model，多模态 image_url，一次可带多张图）。

提示词要点（对应实际业务约束）

要求提示词里的对应条款
一次发多张图先发全部参考图（reference_1..N），再发该批候选（c1..cN），标签顺序固定
参考集本身多样「先归纳参考集的共性画法，不要逐张比对某一张」
只评画风不评内容「人物、发色、瞳色、服装、姿势、镜头、道具、场景不得影响评分；换了角色的同画风图算匹配」
不奖励抄内容「不得因为抄了参考图的内容而加分，也不得因为内容不同而扣分」
要 0-100严格 JSON：style_score 0-100 + 5 个分项（线条/五官头发/上色光影/材质/背景）0-100 + reason + biggest_gap
保守「在两档之间犹豫时取下档」；分项加权与总分差 >15 分时只记录不擅自改分

实测（komori-hikki-style round19，两次独立运行）

候选第 1 次总分第 2 次总分本地 gram ↓我的读图
new（短锚）77627.07更规整、有装饰边框，不如旧版
old（长描述）84672.23更柔和更贴参考
三方同向：大模型打分、本地 gram、我的读图都判「旧版更好」。 但绝对分不稳定：同一条目两次运行差了 10~15 分（77/84 → 62/67）， 说明 0-100 分只能当相对比较用，跨批次比绝对值没有意义 —— 这一点已写进工具输出与报告页脚。

用法

# 先看会发什么（不发请求）
python tools/llm_style_score.py --style cccccanh --images a.jpg --dry-run

# 打分（自动查该画风的参考图）
python tools/llm_style_score.py --style komori-hikki-style --images a.jpg b.jpg --out score.json

# 直接从实验轮次取候选，并写进出图对比报告
python tools/llm_style_score.py --label round19 --style komori-hikki-style --report report.html

4.2 本次改动（「单图调试生图」）

  1. 新增通道选择：生图通道: Gemini | gpt-image-2，状态持久化（data/single_gen_debug_ui_state.json）。
  2. Gemini 路径改为与分析 Tab 完全同源：build_ref_gen_params + resolve_gemini_reference_content（内容锚，需要已加载分析 JSON） + build_gemini_content_postamble（图后重申）。 改前它用 assemble_style_instructions、既不看 prompt_gemini 也不解析 gemini_content_field —— 同一个画风在两个 Tab 会出不同的图，根本没法横向对比。
  3. gpt-image-2 路径：build_first_pass_request → generate_first_image → 可选 run_gpt_image_pipeline（重绘 lines_only + 色调校准(目标=画风参考图) + 线条加墨）， 与分析 Tab 的默认配方一致。
  4. 提示词框在 gpt 通道下作为内容锚使用（placeholder 会切换说明）。
